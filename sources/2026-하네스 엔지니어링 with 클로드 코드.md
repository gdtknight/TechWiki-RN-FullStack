## 핵심 요약 (Core Thesis)

책 전체를 관통하는 문장은 "모델이 아니라 하네스가 결과를 결정합니다."이다 (p.6, p.9). 하네스의 정의: "하네스란 모델의 가중치를 바꾸지 않고, 모델 바깥의 권한·도구·검증·상태·관측을 설계해 에이전트가 일하게 하는 환경입니다." (p.34)

출발점은 단일 에이전트의 구조적 한계다. "같은 모델, 같은 컨텍스트, 같은 가정으로 네 단계를 수행하기 때문에, 처음에 놓친 가정을 검증 단계에서도 다시 놓치기 쉽습니다." (p.29, 네 단계는 계획 → 코드 → 검증 → 자기 수정) 그래서 역할을 나눈 **에이전트 팀**과, 규칙을 프롬프트가 아니라 구조로 강제하는 설계를 제안한다: "프롬프트는 말로 지시합니다. 하네스는 구조로 강제합니다." (p.36)

구체적인 도구는 [Claude Code](https://code.claude.com/docs)의 서브에이전트(`.claude/agents/`), 스킬(`.claude/skills/`), 에이전트 팀이다. 위키의 개념 정리는 [[Claude Code Harness Design (Agents, Skills, and Orchestration)]].

## 주요 챕터 및 구조

### 1부 하네스란 무엇인가 (1–2장)
- **1장 왜 하네스인가 (p.27–38)**: 단일 에이전트의 자기 검증 실패, 모델을 고정하고 환경만 바꾼 세 실험(책 표: 49.5 → 79.3 등, p.30–31), 소프트웨어 공학의 "위임의 사다리"와 "안쪽은 확률론, 가장자리는 결정론" (p.32–33), 용어 관계 "하네스 엔지니어링 ⊇ 컨텍스트 엔지니어링 ⊇ 프롬프트 엔지니어링" (p.35), 세 가지 오해(프롬프트의 확장판, 프레임워크, IDE) (p.36–38).
- **2장 30분 Quick Start (p.39–54)**: 파일 5개(에이전트 2 + 스킬 1 + `CLAUDE.md` + `_workspace/`)로 만드는 커밋 메시지 생성-검증 2인 팀 (p.43). "파일이 없으면 존재하지 않는다." (p.42) 재호출 상한 2회로 무한 루프를 막는다 (p.44, p.47).

### 2부 하네스 구성하기 (3–6장)
- **3장 책임 분리 (p.57–69)**: 에이전트 = 누가, 스킬 = 어떻게, 오케스트레이터 = 언제·누구와 (p.58, p.60–61). 섞이면 재사용 불가·병렬 불가·누락 반복·컨텍스트 폭발 (p.59). 안티패턴 4가지 (p.66–68).
- **4장 에이전트 정의 (p.70–91)**: 에이전트 파일은 "역할 계약서" (p.60). 본문 7개 섹션(핵심 역할, 작업 원칙, 입출력 프로토콜, 팀 통신 프로토콜, 에러 핸들링, 협업, 품질 자체 검증) (p.73–77). `tools` 필드로 거는 가드레일 (p.77–78). 모델은 추론 깊이로, 도구는 부작용 범위로 고른다 (p.80–82).
- **5장 스킬 설계 (p.92–109)**: description이 호출을 결정한다(동사 나열 → 트리거 상황 → 경계 조건) (p.95–96). Progressive Disclosure 3층(description / SKILL.md 본문 / references) (p.97–99). 규칙에 이유를 붙이는 Why-First (p.99–100).
- **6장 오케스트레이터 (p.110–131)**: 리더가 모든 메시지를 중개하는 "우체국" 대신, 리더는 이벤트 루프처럼 알림에만 반응하고 팀원끼리 직접 메시지를 주고받게 한다 (p.112–113). 구성(TeamCreate) · 작업 큐(TaskCreate, `depends_on`) · 메시지(SendMessage) · 파일(`_workspace/`)의 네 전달 층 (p.114). 팀 크기는 작게 (p.125), 관측과 경계면 (p.127–130).

### 3부 하네스 스킬로 구성하기 (7–10장)
- **8장 여섯 가지 아키텍처 패턴 (p.152–171)** — 정독: 파이프라인, 팬아웃·팬인, 전문가 풀, 생성-검증, 감독자, 계층적 위임. 원칙은 "문제의 구조를 정확히 파악하면 패턴은 자연스럽게 따라옵니다", 실전은 복합 패턴, 계층은 2단계 이내 (p.154). → [[Multi-Agent Orchestration]]
- 7장(메타스킬과 6단계 파이프라인), 9장(팀/서브에이전트/하이브리드), 10장(CLAUDE.md 포인터, drift 감지) — 목차만.

### 4부 실전편 (11–14장) — 목차만
코드 리뷰 자동화, 풀스택 기능 구현, 레거시 마이그레이션, 디버깅/RCA 팀 (p.9).

### 부록
- **D 토큰 경제와 레퍼런스 아키텍처 (p.295–)** — 앞부분 정독: 에이전트 비용은 입력이 대부분이고(입력:출력 약 100:1), 캐시 히트율이 첫 번째 레버라는 주장 (p.296–299). 캐시를 지키는 3원칙(안정적 접두사, 추가 전용, 바이트 동일 접두사) (p.298). → [[Context Engineering]]
- A(설치), B(안티패턴 카탈로그), C(트러블슈팅 20선) — 목차만.

## Claude Code 공식 문서와 다른 점 (2026-10-23 대조)

이 책은 Claude Code의 파일 형식과 도구를 많이 다룬다. Claude Code는 빠르게 바뀌므로 아래 차이가 생겼다. 대조한 문서: [*Create custom subagents*](https://code.claude.com/docs/en/sub-agents), [*Extend Claude with skills*](https://code.claude.com/docs/en/skills), [*Orchestrate teams of Claude Code sessions*](https://code.claude.com/docs/en/agent-teams), [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), [*Pricing*](https://platform.claude.com/docs/en/about-claude/pricing). 로컬 버전은 Claude Code 2.1.309.

| 책 (PDF 쪽) | 공식 문서 | 판정 |
|---|---|---|
| 팀은 `TeamCreate`로 만들고 `TeamDelete`로 해체한다 (p.114–115, p.125–126) | CHANGELOG 2.1.178: "Agent teams: removed the `TeamCreate` and `TeamDelete` tools. With `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` set, every session now has one implicit team — spawn teammates directly with the Agent tool's `name` parameter, no setup step needed." | **바뀜**. 지금은 Agent 도구에 `name`을 주면 팀원이 됨 |
| (6장 전체가 팀 기능을 기본 도구로 설명) | *Agent teams*: "Agent teams are experimental and disabled by default." | 책에서 이 전제를 찾지 못함 (책 전체 텍스트에서 `EXPERIMENTAL`·`AGENT_TEAMS`·"실험적"을 검색했고, 설치를 다룬 부록 A의 팀 설명(p.274–275)에도 없음) |
| "공식 문서는 '2개 이상의 에이전트가 협업할 때는 반드시 에이전트 팀을 먼저 검토한다'고 강하게 권고합니다." (p.126) | *Agent teams*: "Before you set up a team, check whether a lighter option does the job." 순차 작업·같은 파일 수정·의존성이 많은 일은 "a single session or subagents are more effective." | **방향이 반대**. 공식 문서는 가벼운 방법을 먼저 권함 |
| 에이전트 `name`은 "파일명과 반드시 일치시켜야 합니다." (p.46, p.80) | *Subagents*: "The filename doesn't have to match." | **다름** |
| `model`을 생략하면 부모 세션 모델을 상속, 기본값 `inherit` (p.46, p.79–80) | 우선순위: 호출 시 `model` 인자 → 프론트매터 → `CLAUDE_CODE_SUBAGENT_MODEL` 환경 변수 → 메인 대화 모델 | **대체로 맞지만 단순화**. 호출할 때 넘긴 모델과 환경 변수가 먼저 적용됨 |
| 스킬의 `allowed-tools`로 "더 엄격하게 권한을 제한하고 싶다면 `Bash(git diff:*)`처럼 인자 패턴까지 지정할 수 있습니다." (p.49) | *Skills*: `allowed-tools`는 그 턴 동안 묻지 않고 쓸 도구를 **미리 허가**한다. "It does not restrict which tools are available: every tool remains callable". 빼려면 `disallowed-tools` | **반대 의미**. 제한이 아니라 허가 |
| 에이전트 프론트매터 공식 필드는 16개 (p.79) | 현재 *Subagents* 표에는 `autoCompactWindow`, `omitClaudeMd`, `experimental` 등이 더해져 19개 | 버전에 따라 늘어남 |
| 스킬 목록 예산 "전체 컨텍스트 윈도의 약 1%" (p.93) | *Skills*: "The budget scales at 1% of the model's context window." | **맞음**. 다만 책이 함께 든 "기본 대체 한도 약 8,000자"는 현재 문서에서 찾지 못함 (미확인) |
| `disallowedTools`가 먼저 적용되고 남은 집합에 `tools`가 적용, 둘 다에 있으면 제거 (p.78, p.82) | *Subagents*: "If both are set, `disallowedTools` is applied first, then `tools` is resolved against the remaining pool. A tool listed in both is removed." | **맞음** |
| 에이전트 저장 위치 5곳과 우선순위 (p.83) | *Subagents* "Choose the subagent scope" 표와 같음 | **맞음** |
| 팀 규모: 3–5명 적정 (p.125, p.131) | *Agent teams*: "Start with 3-5 teammates for most workflows." | **맞음** |
| 가격표: Opus 4.6 입력 $15 / 캐시 $1.50 / 출력 $75, Haiku 4.5 $0.80 / $0.08 / $4 ("2026 Q2 Anthropic 가격 기준") (p.297) | *Pricing*: Opus 4.6 $5 / $0.50 / $25, Haiku 4.5 $1 / $0.10 / $5. 책의 숫자는 Opus 4.1·Haiku 3.5의 가격과 같음 | **틀림** (Sonnet 4.6 $3 / $0.30 / $15는 맞음). 같은 쪽의 비용 시뮬레이션 숫자도 이 가격에 기대므로 그대로 쓰지 않음 |
