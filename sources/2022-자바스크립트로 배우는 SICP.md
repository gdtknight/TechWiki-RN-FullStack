# 2022-자바스크립트로 배우는 SICP (Structure and Interpretation of Computer Programs, JavaScript Edition)

## 1. 핵심 테제 (Core Thesis)
컴퓨터 과학의 전설적 명저 *SICP(마법사 책)* 를 기존 Scheme 대신 **[[JavaScript (ECMAScript)|JavaScript(ECMAScript)]]** 의 부분집합으로 전면 재집필한 고전(총 883페이지)이다. 프레임워크나 문법 유행을 넘어 프로그램의 본질인 **3대 추상화 기법(함수 추상화, 데이터 추상화, 메타언어적 추상화)** 을 심도 있게 다룬다. 특히 **클로저(`pair`, `head`, `tail`)만으로 복합 데이터를 구축하는 원리(Ch 2)** 와 **평가의 환경 모형(Environment Model of Evaluation, Ch 3.2)**, **메타순환적 평가기(`evaluate`/`apply`, Ch 4.1)** 는 [[JavaScript Execution Context, Closures, and Prototype]]과 [[React Fiber and Reconciliation]]의 근간을 이루는 컴퓨터 과학의 정수를 보여준다.

## 2. 챕터별 상세 요약 (Chapter-by-Chapter Summary)

### 제1장: 함수를 이용한 추상화 (Building Abstractions with Functions, p.42–139)
- **1.1 프로그래밍의 기본 요소 (p.45–78)**: 표현식(Expressions)과 문장(Statements), 이름 짓기와 환경(Environment), 조건부 표현식(`? :`)과 술어(Predicates), 인자 우선 평가(Applicative-order evaluation) vs 정규 순서 평가(Normal-order evaluation), 블랙박스 추상화로서의 함수와 블록 구조(렉시컬 스코핑)를 정의한다.
- **1.2 함수와 과정 — 함수가 생성하는 계산 과정 (p.79–109)**: 재귀적 정의(Recursive syntax)와 실제 실행 시의 **선형 재귀적 과정(Linear recursive process, 지연된 연산 사슬이 쌓임)** 및 **선형 반복적 과정(Linear iterative process, 고정된 수의 상태 변수만 갱신하며 꼬리 호출 최적화 가능)** 을 명확히 구분한다. 트리 재귀(Tree recursion)와 증가 차수($\Theta(n)$, $\Theta(\log n)$) 분석을 다룬다.
- **1.3 고차 함수를 이용한 추상의 정식화 (p.110–139)**: 함수를 인자로 받고 함수를 반환(`=>` 람다 표현식)하는 고차 함수(Higher-Order Functions)를 통해 수치 적분, 고정점(Fixed point) 탐색, 뉴턴 방법을 일반화한다.

### 제2장: 데이터를 이용한 추상화 (Building Abstractions with Data, p.140–305)
- **2.1 데이터 추상화 입문 (p.144–161)**: 생성자(Constructor)와 선택자(Selector)를 분리하는 **추상화 장벽(Abstraction Barriers)** 을 설계한다. 특히 배열이나 객체 리터럴 없이 오직 고차 함수와 클로저만으로 `pair(x, y)`, `head(z)`, `tail(z)`를 구현하며 **"데이터란 결국 함수(절차)와 클로저의 또 다른 형태"** 임을 증명한다(p.152).
- **2.2 위계적 데이터와 닫힘 성질 (p.162–217)**: 쌍(`pair`)의 원소가 다시 쌍이 될 수 있는 **닫힘 성질(Closure Property of Data Operations)** 로 연결 리스트와 트리 구조를 구축한다. `map`, `filter`, `accumulate`(`reduce`)로 이어지는 **열거-필터-변환-누적(Signal-flow / Sequence Operations)** 파이프라인과 그림 언어(Picture Language)의 계층적 조합을 다룬다.
- **2.3–2.5 기호 데이터와 다중 표현 (p.218–305)**: 기호 미분(Symbolic Differentiation), 허프만 인코딩 트리(Huffman Encoding Trees), 태그가 붙은 데이터(Tagged Data)와 **데이터 지향 프로그래밍(Data-Directed Programming)**, 메시지 패싱(Message Passing)을 통한 다형성 시스템을 구현한다.

### 제3장: 모듈성, 객체, 상태 (Modularity, Objects, and State, p.306–483)
- **3.1 배정과 지역 상태 (p.308–329)**: 변수 배정(`=`)의 도입이 어떻게 지역 상태를 가진 객체를 가능하게 하는지, 동시에 왜 **치환 모형(Substitution Model)을 파괴하고 참조 투명성(Referential Transparency)을 무너뜨리는지** 분석한다. 이는 [[React Hooks and Component Design Patterns]] 및 [[Offline-First and Mobile State Management]]에서 왜 불변성(Immutability)을 고집하는지에 대한 근본적인 수학적·전산학적 해답이다.
- **3.2 평가의 환경 모형 (The Environment Model of Evaluation, p.330–351)**: 치환 모형을 대체하기 위해 프레임(Frame)과 바깥 환경 포인터(Enclosing Environment Pointer)로 이루어진 **환경 구조(Environment Structure)** 를 도입한다. 함수 정의가 평가될 때 현재 환경에 대한 포인터를 캡처한 함수 객체(클로저)가 만들어지고, 함수 호출 시 새 프레임이 생성되어 렉시컬 환경에 연결되는 과정을 다이어그램으로 완벽히 규명한다([[JavaScript Execution Context, Closures, and Prototype]]과 직결).
- **3.3–3.4 변경 가능 데이터와 동시성 (p.352–431)**: 변경 가능한 리스트·큐·테이블, 디지털 회로 및 제약 조건 전파 시뮬레이터를 구현하고, 공유 상태를 다루는 동시성 시스템에서의 직렬화(Serializer)와 교착 상태(Deadlock)를 다룬다.
- **3.5 스트림 (Streams, p.432–483)**: 상태 배정으로 인한 시간 의존성 문제를 극복하기 위해, **지연 평가(Delayed Evaluation, `() => ...` 썽크와 메모이제이션)** 를 활용한 무한 스트림(`stream_map`, `stream_filter`, 소수 체, 신호 처리 루프)을 구축한다.

### 제4장: 메타언어적 추상화 (Metalinguistic Abstraction, p.484–665)
- **4.1 메타순환적 평가기 (The Metacircular Evaluator, p.487–542)**: JavaScript로 JavaScript 자체의 인터프리터를 작성한다. 구문 분석(`parse`)과 함께 모든 언어 런타임의 심장부인 **`evaluate(component, env)`와 `apply(fun, args)`의 상호 재귀 루프**를 구현하고, 구문 분석과 실행을 분리하여 성능을 최적화한다.
- **4.2–4.4 변형 언어들 (p.543–665)**: 인자 평가를 늦추는 느긋한 평가기(Lazy Evaluator, Thunk), 자동 백트래킹을 수행하는 비결정론적 컴퓨팅(`amb` 평가기), 그리고 패턴 매칭과 단일화(Unification)에 기반한 논리 프로그래밍(Query 시스템)을 구현한다.

### 제5장: 레지스터 기계를 이용한 계산 (Computing with Register Machines, p.666–820)
- **5.1–5.5 레지스터 기계, 가비지 컬렉션, 컴파일러 (p.668–820)**: 고수준 언어가 물리적 하드웨어에서 어떻게 실행되는지 보이기 위해 레지스터와 스택(`save`/`restore`)을 가진 기계를 설계한다. 연속(Continuation) 제어를 통해 재귀 과정을 반복적 레지스터 연산으로 변환하고, **Stop-and-Copy 가비지 컬렉션(p.719)**, **명시적 제어 평가기(Explicit-Control Evaluator, p.734)**, 그리고 **컴파일러(p.762)** 까지 밑바닥부터 완성한다.
