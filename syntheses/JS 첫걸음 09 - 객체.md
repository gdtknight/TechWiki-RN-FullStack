## 1. 객체란?

### 비유로 이해하기: 이름표 달린 서랍장

[[JS 첫걸음 08 - 배열|레슨 08]]의 배열은 **번호 붙은 사물함 한 줄**이었습니다. 순서대로 담기에는 좋지만, 강아지 한 마리의 정보를 배열에 담으면 어떨까요?

```js
const dog = ["초코", 3, "갈색", true];
```

`dog[1]`이 나이인지 몸무게인지, `dog[3]`의 `true`가 무슨 뜻인지 알 수 없습니다.

**객체**(object)는 **서랍마다 이름표가 붙은 서랍장**입니다. 번호 대신 **이름**으로 찾습니다.

```js
const dog = {
  name: "초코",
  age: 3,
  color: "갈색",
  isFriendly: true,
};
```

이제 "이름 서랍", "나이 서랍"처럼 뜻이 분명합니다. 입문서는 강아지를 예로 들어, 객체는 이름·몸무게·색깔·품종 같은 **속성**을 가진 현실의 사물을 나타낸다고 설명합니다 (p.72).

MDN: "An object is a collection of properties, and a property is an association between a name (or key) and a value."

| 용어 | 뜻 | 위 예에서 |
|---|---|---|
| **속성** (property) | 이름과 값의 한 쌍 | `name: "초코"` |
| **키** (key) | 속성의 이름 (서랍 이름표) | `name` |
| **값** (value) | 서랍 안에 든 것 | `"초코"` |

### 배열과 객체, 언제 무엇을?

입문서의 기준이 명쾌합니다 (p.92): "Whenever you need a list of something, you will be using an array. Whenever you want to represent something with properties that have descriptive names, it is better to use an object."

| | 배열 | 객체 |
|---|---|---|
| 기호 | `[ ]` | `{ }` |
| 찾는 법 | 번호 (0, 1, 2…) | 이름 (`name`, `age`…) |
| 어울리는 것 | **목록**: 학생 명단, 점수들, 장보기 목록 | **하나의 대상**: 학생 한 명, 상품 하나, 설정 |

어떤 것이 속성이 될 만한지 헷갈리면, 입문서의 문장 틀에 넣어 보세요. "**강아지는 이름을 가지고 있다**", "강아지는 색깔을 가지고 있다" (p.87: "*objectname* has a(n) *property name*"). 참/거짓 속성이라면 "강아지는 친근**하다**"처럼 읽습니다.

## 2. 객체 만들고 꺼내기

### 2.1 만들기

**중괄호 `{ }`** 안에 `키: 값`을 **쉼표**로 나눠 씁니다 (입문서 p.86).

```js
const dog = {
  name: "초코",
  age: 3,
  color: "갈색",
  isFriendly: true,
};
```

- 키와 값 사이는 **콜론 `:`**, 속성과 속성 사이는 **쉼표 `,`** 입니다.
- 값에는 어떤 자료형이든 넣을 수 있습니다 (입문서 p.92: "object properties can be of any type").
- 마지막 속성 뒤의 쉼표는 있어도 되고 없어도 됩니다.

### 2.2 꺼내기: 점과 대괄호

두 가지 방법이 있습니다 (입문서 p.87; MDN: "Property accessors come in two syntaxes: dot notation and bracket notation.").

```js
console.log(dog.name);      // 초코   ← 점 표기법
console.log(dog["age"]);    // 3      ← 대괄호 표기법 (키를 따옴표로)
```

평소에는 짧고 읽기 쉬운 **점 표기법**을 씁니다. 대괄호는 이럴 때 꼭 필요합니다.

**① 키가 변수에 들어 있을 때** (입문서 p.88)

```js
const key = "age";
console.log(dog[key]);   // 3          ← 변수 key의 값 "age"로 찾음
console.log(dog.key);    // undefined  ← "key"라는 이름의 서랍을 찾음
```

**② 키에 띄어쓰기 같은 특수 문자가 있을 때**

```js
const info = { "favorite food": "고구마" };
console.log(info["favorite food"]);   // 고구마
```

MDN: "a property name that has a space or a hyphen, that starts with a number, or that is held inside a variable can only be accessed using the bracket notation."

### 2.3 없는 속성을 꺼내면?

에러가 아니라 **`undefined`** 입니다. MDN: "Nonexistent properties of an object have the value `undefined` (and not `null`)."

```js
console.log(dog.weight);   // undefined
```

> 배열의 `length`도 사실 점 표기법으로 꺼낸 **속성**입니다. 입문서는 속성은 괄호가 없고, 메서드(함수)는 괄호가 있다는 차이를 짚습니다 (p.87).

## 3. 바꾸기, 추가하기, 지우기

```js
dog.color = "흰색";     // 있는 속성 바꾸기
dog.weight = 4.5;       // 없는 속성에 대입하면 새로 추가됨
console.log(dog);
// { name: '초코', age: 3, color: '흰색', isFriendly: true, weight: 4.5 }

delete dog.weight;      // 속성 지우기
console.log(dog);
// { name: '초코', age: 3, color: '흰색', isFriendly: true }
```

- 바꾸기는 입문서 p.87, 지우기는 MDN: "You can remove a non-inherited property using the `delete` operator."
- `dog`가 `const`인데도 바뀝니다. [[JS 첫걸음 08 - 배열|레슨 08]]의 `const` 배열과 같은 이유입니다. 서랍장 **자체를 바꿔 끼우는 것**(`dog = {...}`)만 막히고, 서랍 안은 자유롭게 바꿀 수 있습니다.

## 4. 객체와 배열 섞기

실제 프로그램의 데이터는 대부분 객체와 배열이 섞여 있습니다 (입문서 p.89).

### 4.1 객체 안의 객체, 객체 안의 배열

```js
const student = {
  name: "지수",
  grade: 5,
  address: {              // 객체 안의 객체
    city: "서울",
    district: "마포구",
  },
  hobbies: ["축구", "그림"],   // 객체 안의 배열
};

console.log(student.address.city);   // 서울
console.log(student.hobbies[1]);     // 그림
student.hobbies.push("코딩");
console.log(student.hobbies);        // [ '축구', '그림', '코딩' ]
```

점과 대괄호를 **이어서** 쓰면 안쪽으로 계속 들어갈 수 있습니다 (입문서 p.90). `student.address.city`는 "학생의 → 주소의 → 도시"로 읽습니다.

### 4.2 객체가 담긴 배열 ⭐

**가장 많이 쓰는 모양**입니다. 쇼핑몰의 상품 목록, 게시판의 글 목록, 친구 목록이 모두 이 모양입니다 (판단).

```js
const products = [
  { name: "연필", price: 500 },
  { name: "공책", price: 1500 },
  { name: "필통", price: 4000 },
];

console.log(products[1].name);   // 공책  (1번 칸의 → 이름)
```

`products[1].name`은 입문서의 `addresses[0].street`와 같은 모양입니다 (p.91).

레슨 08에서 배운 배열 도구를 그대로 쓸 수 있습니다.

```js
// 하나씩 출력
for (const p of products) {
  console.log(`${p.name}: ${p.price}원`);
}
// 연필: 500원
// 공책: 1500원
// 필통: 4000원

// 2000원 미만만 고르기
const cheap = products.filter(p => p.price < 2000);
// [ { name: '연필', price: 500 }, { name: '공책', price: 1500 } ]

// 이름만 뽑기
const names = products.map(p => p.name);
// [ '연필', '공책', '필통' ]

// 이름으로 찾기
const found = products.find(p => p.name === "필통");
// { name: '필통', price: 4000 }
```

이 네 줄의 모양은 앞으로 React 화면을 만들 때 거의 매일 보게 됩니다 (판단).

## 5. 객체 훑기

### 5.1 `for...in`: 키를 하나씩

`for...in`은 객체의 **키**를 하나씩 꺼냅니다 (입문서 p.128).

```js
const car = { model: "Golf", make: "Volkswagen", year: 1999 };

for (const key in car) {
  console.log(key, car[key]);
}
```

결과:

```
model Golf
make Volkswagen
year 1999
```

`car[key]`로 값을 꺼낼 때 **대괄호**를 쓰는 것에 주목하세요. `key`가 변수이기 때문입니다 (2.2절의 ①).

| 반복 | 꺼내는 것 | 주로 쓰는 곳 |
|---|---|---|
| `for...of` (레슨 08) | **값** | 배열 |
| `for...in` | **키** | 객체 |

입문서: "the for in loop is getting the property names (keys) and not the values. The for of is doing the opposite" (p.129). 배열에는 `for...in`보다 `for`나 `for...of`가 낫습니다 (MDN *for...in*: "It is better to use a `for` loop with a numeric index, `Array.prototype.forEach()`, or the `for...of` loop").

### 5.2 `Object.keys` / `values` / `entries`: 배열로 바꾸기

객체를 **배열로 바꾸면** 레슨 08의 배열 도구를 모두 쓸 수 있습니다 (입문서 p.129–131).

```js
console.log(Object.keys(car));     // [ 'model', 'make', 'year' ]       ← 키만
console.log(Object.values(car));   // [ 'Golf', 'Volkswagen', 1999 ]    ← 값만
console.log(Object.keys(car).length);   // 3  ← 속성이 몇 개인지
```

`Object.entries`는 `[키, 값]` 쌍의 배열을 돌려줍니다. MDN: "returns an array of a given object's own enumerable string-keyed property key-value pairs."

```js
for (const [key, value] of Object.entries(car)) {
  console.log(`${key}: ${value}`);
}
// model: Golf
// make: Volkswagen
// year: 1999
```

`const [key, value]`는 `[키, 값]` 배열의 두 칸을 각각 `key`와 `value`라는 이름으로 꺼내는 문법입니다 (입문서 p.131의 예). **배열 구조 분해**라고 부르며, 시리즈를 마친 뒤 [[JavaScript Core Syntax and Modern ES6+ Fundamentals]] 4.1절에서 자세히 볼 수 있습니다.

## 6. 메서드: 객체 안의 함수

객체의 값으로 **함수**를 넣을 수도 있습니다. 이런 속성을 **메서드**(method)라고 합니다. MDN: "a method is a property of an object that is a function." 입문서는 속성이 "가진 것"이라면 메서드는 "할 수 있는 행동"이라고 설명합니다 (p.72, p.86).

```js
const robot = {
  name: "또봇",
  sayHi() {
    console.log("삐빅, 안녕!");
  },
  add: (a, b) => a + b,
};

robot.sayHi();                // 삐빅, 안녕!
console.log(robot.add(2, 3)); // 5
```

`sayHi() { ... }`는 `function`을 생략한 줄임 모양입니다. MDN: "A shorthand notation is available, so that the keyword `function` is no longer necessary."

사실 우리는 메서드를 계속 써 왔습니다. `console.log`는 `console` 객체의 `log` 메서드이고, `fruits.push`는 배열의 `push` 메서드입니다 (판단, 입문서 p.78: "Methods are functions on a certain object.").

> [!note] `this`는 다루지 않아요
> 메서드 안에서 자기 객체를 가리키는 `this`라는 낱말이 있습니다. 동작 규칙이 복잡해서 이 시리즈에서는 다루지 않습니다. 시리즈를 마친 뒤 [[JavaScript Execution Context, Closures, and Prototype]]에서 볼 수 있습니다.

> [!tip] 줄임 모양: 키와 변수 이름이 같을 때
> ```js
> const title = "해리 포터";
> const pages = 300;
> const book = { title, pages };   // { title: title, pages: pages }와 같음
> console.log(book);               // { title: '해리 포터', pages: 300 }
> ```
> MDN *Object initializer*의 "Shorthand property names". 다른 사람의 코드에서 자주 보입니다.

## 7. 객체 복사의 함정

[[JS 첫걸음 08 - 배열|레슨 08]]의 8.2절과 같은 이야기가 객체에도 똑같이 적용됩니다.

```js
const a = { score: 1 };
const b = a;          // 복사가 아니라 같은 서랍장에 이름표만 하나 더
b.score = 99;
console.log(a.score); // 99  ← a도 바뀜!
```

진짜 복사본이 필요하면 **`{ ...a }`** 로 펼쳐서 새 객체를 만듭니다.

```js
const c = { ...a };
c.score = 5;
console.log(a.score, c.score);   // 99 5  ← 따로따로

const upgraded = { ...a, level: 2 };   // 펼치고 속성 추가
console.log(upgraded);                 // { score: 99, level: 2 }
```

> [!warning] 내용이 같아도 다른 객체는 `===`가 `false`
> ```js
> console.log({ x: 1 } === { x: 1 });   // false
> ```
> `===`로 객체를 비교하면 **내용**이 아니라 **같은 서랍장인지**를 봅니다. 서랍 속 내용이 같아도 서랍장이 두 개면 다릅니다. `const k2 = k1;`처럼 같은 서랍장을 가리킬 때만 `true`입니다 (Node.js 실행 결과). 이 성질은 React가 화면을 다시 그릴지 결정할 때 쓰입니다 ([[JavaScript Core Syntax and Modern ES6+ Fundamentals]] 1.5절 표의 ②).

## 8. 없는 속성을 깊게 꺼낼 때: 에러와 `?.`

2.3절에서 없는 속성은 `undefined`라고 했습니다. 그런데 그 `undefined`에서 **한 번 더** 꺼내면 에러가 납니다.

```js
console.log(student.pet);        // undefined  (pet 속성이 없음)
console.log(student.pet.name);   // ❌ 에러!
```

결과:

```
TypeError: Cannot read properties of undefined (reading 'name')
```

"`undefined`에서 `name`을 읽으려 했다"는 뜻입니다. 빈 서랍(`undefined`) 안에서 또 서랍을 찾으려 한 것입니다. 앞으로 **가장 자주 만날 에러 중 하나**입니다 (판단).

**`?.`(옵셔널 체이닝)** 을 쓰면 중간이 비어 있을 때 에러 대신 `undefined`를 돌려줍니다. MDN: "If the object accessed or function called using this operator is `undefined` or `null`, the expression short circuits and evaluates to `undefined` instead of throwing an error."

```js
console.log(student.pet?.name);       // undefined  ← 에러 없음
console.log(student.address?.city);   // 서울       ← 있으면 정상
```

"`pet`이 **있으면** 그 `name`을, 없으면 `undefined`"로 읽습니다.

## 9. 정리

| 낱말 | 뜻 |
|---|---|
| 객체 | 이름표 달린 서랍장. `{ 키: 값, ... }` |
| 속성 / 키 / 값 | 이름과 값의 한 쌍 / 그 이름 / 그 값 |
| 점 표기법 | `obj.key`. 평소에 씀 |
| 대괄호 표기법 | `obj["key"]`, `obj[변수]`. 키가 변수이거나 특수 문자가 있을 때 |
| `delete obj.key` | 속성 지우기 |
| 객체가 담긴 배열 | `[{...}, {...}]`. 목록 데이터의 기본 모양 |
| `for...in` | 객체의 **키**를 하나씩 |
| `Object.keys` / `values` / `entries` | 키 배열 / 값 배열 / `[키, 값]` 배열 |
| 메서드 | 값이 함수인 속성. `obj.method()` |
| `{ ...obj }` | 객체 복사·합치기 |
| `?.` | 중간이 `undefined`/`null`이면 에러 대신 `undefined` |

## 10. 자주 하는 실수

| 잘못 쓴 코드 | 결과 | 무엇이 문제인가 |
|---|---|---|
| `{ name: "초코" age: 3 }` | `SyntaxError: Unexpected identifier 'age'` | 속성 사이에 **쉼표**가 빠졌습니다. |
| `{ name: "초코"; age: 3 }` | `SyntaxError: Unexpected token ';'` | 속성 사이는 세미콜론이 아니라 **쉼표**입니다. |
| `const key = "age"; dog.key` | `undefined` | 점 표기법은 `"key"`라는 이름을 찾습니다. 변수로 찾으려면 `dog[key]`. |
| `dog.Name` | `undefined` | 대소문자가 다릅니다 (`name` ≠ `Name`). 에러가 아니라 `undefined`라서 알아채기 어렵습니다. |
| `student.pet.name` (pet 없음) | `TypeError: Cannot read properties of undefined (reading 'name')` | 없는 속성 안을 또 꺼냈습니다. 8절의 `?.`. |
| `const b = a;` 후 `b`를 수정 | `a`도 바뀜 | 같은 객체를 가리킵니다. `{ ...a }`로 복사합니다. |
| `{ x: 1 } === { x: 1 }`이 `true`일 거라고 생각 | `false` | 서로 다른 두 객체입니다 (7절). |

## 11. 확인 퀴즈

**Q1.** 아래 코드의 출력은?
```js
const cat = { name: "나비", age: 2 };
cat.age += 1;
cat.color = "검정";
console.log(cat);
console.log(Object.keys(cat).length);
```

> [!question]- 정답 보기
> `{ name: '나비', age: 3, color: '검정' }`과 `3`입니다. `age`는 1 늘었고, 없던 `color`가 새로 추가되었습니다.

**Q2.** 아래 두 줄의 출력은?
```js
const prop = "color";
const pen = { color: "파랑" };
console.log(pen[prop]);
console.log(pen.prop);
```

> [!question]- 정답 보기
> `파랑`과 `undefined`입니다. `pen[prop]`은 변수 `prop`의 값 `"color"`로 찾고, `pen.prop`은 `"prop"`이라는 이름의 속성을 찾는데 없습니다.

**Q3.** 아래 데이터에서 "민수"를 꺼내는 코드를 쓰세요.
```js
const team = { name: "번개", members: ["민수", "지수"] };
```

> [!question]- 정답 보기
> `team.members[0]`입니다. 팀의 → 멤버 배열의 → 0번 칸.

**Q4.** 학생 정보(이름, 학년, 좋아하는 과목 목록)를 담는 객체를 자유롭게 만들어 보세요. 배열과 객체 중 무엇을 어디에 썼는지 설명해 보세요.

> [!question]- 예시 답안
> ```js
> const me = {
>   name: "김코딩",
>   grade: 5,
>   favoriteSubjects: ["수학", "과학"],
> };
> ```
> 학생 **한 명**은 이름 붙은 속성이 있으므로 객체, 좋아하는 과목은 **목록**이므로 배열을 썼습니다 (1절의 기준).

**Q5.** 아래 상품 목록에서 가격이 3000원 이상인 상품의 **이름만** 담은 배열을 만드세요. (힌트: `filter` 다음에 `map`)
```js
const products = [
  { name: "연필", price: 500 },
  { name: "필통", price: 4000 },
  { name: "가방", price: 25000 },
];
```

> [!question]- 정답 보기
> ```js
> const names = products
>   .filter(p => p.price >= 3000)
>   .map(p => p.name);
> console.log(names);   // [ '필통', '가방' ]
> ```
> `filter`가 돌려준 새 배열에 바로 `.map`을 이어 붙였습니다.

**Q6.** 아래 코드에서 `original.score`가 바뀌지 않게 고치세요.
```js
const original = { score: 10 };
const copy = original;
copy.score = 0;
```

> [!question]- 정답 보기
> `const copy = { ...original };`로 바꿉니다.

**Q7.** `user.profile.nickname`을 꺼내려는데 `profile`이 없을 수도 있습니다. 에러가 나지 않게 쓰려면?

> [!question]- 정답 보기
> `user.profile?.nickname`입니다. `profile`이 없으면 `undefined`가 나옵니다.

**Q8. (직접 해 보기)** 입문서 연습문제 3.4를 해 보세요 (p.88–89).
1. `myCar` 객체를 만들고 `make`, `model` 등 속성을 넣습니다.
2. `"color"`를 담은 변수를 만들고, 그 변수와 대괄호로 `myCar`의 색깔을 정합니다.
3. `make`와 `model`을 출력합니다.

> [!question]- 예시 답안
> ```js
> const myCar = { make: "Hyundai", model: "Avante", year: 2024 };
> const propName = "color";
> myCar[propName] = "흰색";
> console.log(myCar.make, myCar.model);   // Hyundai Avante
> console.log(myCar);   // { make: 'Hyundai', model: 'Avante', year: 2024, color: '흰색' }
> ```
