## 1. 동기와 비동기

### 비유로 이해하기: 식당의 진동벨

**동기**(synchronous) 방식의 식당을 상상해 봅시다. 손님이 짜장면을 주문하면, 주문받는 사람이 **짜장면이 나올 때까지 계산대 앞에 서서 기다립니다.** 그동안 뒤의 손님은 아무도 주문하지 못합니다.

**비동기**(asynchronous) 방식의 식당은 다릅니다. 주문을 받으면 **진동벨**을 건네주고 바로 다음 손님의 주문을 받습니다. 음식이 다 되면 진동벨이 울리고, 그때 음식을 가져갑니다.

입문서는 금요일 저녁 집안일로 비유합니다 (p.371). 피자를 오븐에 넣고 옆에서 기다리기만 하면 밤이 늦어집니다. 대신 피자가 구워지는 동안 세탁기를 돌리고 빨래를 갭니다. 이렇게 **기다리는 동안 다른 일을 하는 것**이 비동기의 핵심입니다.

### 왜 앱에 비동기가 필요할까?

앱은 기다려야 하는 일이 많습니다. 인터넷으로 날씨 정보를 받아 오기, 사진 불러오기, 서버에 저장하기 같은 일입니다. 입문서: "we can do a call to some API and not wait for the reply but do something useful in the meantime instead." (p.371) 이런 일을 동기로 기다리면 **그동안 화면이 멈춰서** 버튼도 눌리지 않습니다 (판단, [[JavaScript Core Syntax and Modern ES6+ Fundamentals]] 1.5절 표의 ⑦).

## 2. `setTimeout`으로 보는 비동기

### 2.1 기다리지 않고 다음 줄로

[[JS 첫걸음 07 - 함수|레슨 07]]에서 `setTimeout`을 잠깐 봤습니다. 다시 봅니다.

```js
console.log("A");
setTimeout(() => console.log("B (1초 뒤)"), 1000);
setTimeout(() => console.log("C (0.5초 뒤)"), 500);
console.log("D");
```

결과:

```
A
D
C (0.5초 뒤)
B (1초 뒤)
```

`setTimeout`은 "이 함수를 나중에 실행해 줘"라고 **예약만 하고 바로 다음 줄로** 넘어갑니다. MDN: "`setTimeout()` is an asynchronous function, meaning that it returns immediately after scheduling the callback function or code to run. It does not "wait", blocking execution of the lines of code after `setTimeout()` until the scheduled code has run."

그래서 `D`가 `C`와 `B`보다 먼저 나옵니다. 코드에 **적힌 순서**와 **실행되는 순서**가 다를 수 있다는 것, 이것이 비동기의 가장 중요한 특징입니다.

### 2.2 0초로 해도 나중에 실행된다

```js
console.log("Hi there");
setTimeout(() => console.log("Sorry I'm late"), 0);
console.log(4 + 5);
```

결과:

```
Hi there
9
Sorry I'm late
```

0초인데도 `9`보다 늦게 나옵니다 (입문서 p.383–384). MDN: "setting `delay` to 0 will execute in the next event cycle rather than "immediately"." 이유는 6절의 이벤트 루프에서 봅니다.

### 2.3 콜백만으로는 복잡해져요

`setTimeout`처럼 "다 되면 이 함수를 불러 줘"라고 콜백을 건네는 방식이 비동기의 출발점입니다 (입문서 p.371–373). 그런데 "이게 끝나면 저걸 하고, 그게 끝나면 또 다른 걸 하고…"를 콜백으로만 쓰면 콜백 안에 콜백이 계속 들어갑니다. 입문서는 이것을 **콜백 지옥**(callback hell)이라고 부르며, 코드가 옆으로 누운 크리스마스트리처럼 들여쓰기가 깊어진다고 설명합니다 (p.374). 그래서 등장한 것이 **Promise**입니다.

## 3. Promise: "나중에 결과를 줄게"

### 3.1 Promise란?

**Promise**(프로미스, 약속)는 "지금은 결과가 없지만, **나중에 성공하거나 실패한 결과를 줄게**"라는 약속을 담은 객체입니다. MDN: "The `Promise` object represents the eventual completion (or failure) of an asynchronous operation and its resulting value."

1절의 **진동벨**이 바로 Promise입니다. 진동벨을 받은 순간에는 음식이 없지만, 나중에 음식(결과)을 받거나 "재료가 떨어졌어요"(실패) 소식을 듣게 됩니다.

### 3.2 Promise의 세 가지 상태

| 상태 | 뜻 | 진동벨에 비유하면 |
|---|---|---|
| **pending** (대기) | 아직 결과가 없음 | 진동벨을 들고 기다리는 중 |
| **fulfilled** (성공) | 일이 잘 끝남, 결과값 있음 | 벨이 울리고 음식을 받음 |
| **rejected** (실패) | 일이 실패함, 실패 이유 있음 | "재료가 떨어졌어요" |

(MDN *Promise*: "pending: initial state, neither fulfilled nor rejected. / fulfilled: meaning that the operation was completed successfully. / rejected: meaning that the operation failed.")

```js
const p = new Promise(resolve => setTimeout(() => resolve("완료"), 100));
console.log(p);                          // Promise { <pending> }
setTimeout(() => console.log(p), 200);   // Promise { '완료' }
```

(출력 모양은 Node.js 기준입니다. 브라우저 콘솔에서는 모양이 조금 다를 수 있습니다.)

### 3.3 Promise 만들기

```js
const promise = new Promise((resolve, reject) => {
  const ok = true;
  if (ok) {
    resolve("성공!");    // 성공했다고 알림 + 결과값
  } else {
    reject("실패...");   // 실패했다고 알림 + 실패 이유
  }
});
```

`new Promise`에 함수를 하나 건넵니다. 그 함수는 **`resolve`와 `reject`라는 두 콜백**을 받습니다 (입문서 p.374–375).
- 일이 잘 끝나면 `resolve(결과)`를 부릅니다.
- 실패하면 `reject(이유)`를 부릅니다.

> 처음에는 Promise를 **직접 만들 일이 별로 없습니다.** 대부분은 `fetch`(4.4절)처럼 이미 Promise를 돌려주는 함수를 **쓰는** 쪽입니다 (판단). 만드는 법은 "이렇게 생겼구나" 정도로 보고 넘어가도 됩니다.

### 3.4 결과 꺼내기: `.then()`과 `.catch()`

```js
promise
  .then(value => console.log("then:", value))
  .catch(err => console.log("catch:", err));

console.log("Promise 다음 줄");
```

결과:

```
Promise 다음 줄
then: 성공!
```

- `.then(함수)`: **성공했을 때** 실행할 함수. 결과값을 받습니다.
- `.catch(함수)`: **실패했을 때** 실행할 함수. 실패 이유를 받습니다 (입문서 p.375).
- 이번에도 `Promise 다음 줄`이 먼저 나왔습니다. `.then`에 건넨 함수는 결과가 준비된 **뒤에** 실행됩니다.

`reject`를 부르면 `.catch` 쪽이 실행됩니다.

```js
new Promise((resolve, reject) => reject("주문 실패"))
  .then(v => console.log("then:", v))
  .catch(e => console.log("catch:", e));
// catch: 주문 실패
```

`.then`은 다시 Promise를 돌려주므로 **줄줄이 이어 붙일 수** 있습니다. 앞 `.then`이 `return`한 값이 다음 `.then`으로 넘어갑니다 (입문서 p.375–376).

```js
new Promise(resolve => resolve(1))
  .then(n => { console.log(n); return n + 1; })    // 1
  .then(n => { console.log(n); return n * 10; })   // 2
  .then(n => console.log(n));                       // 20
```

## 4. `async` / `await`: 순서대로 읽히게 쓰기

### 4.1 기본 모양

`.then`을 줄줄이 잇는 대신, **위에서 아래로 읽히는** 코드로 쓸 수 있게 해 주는 문법입니다 (입문서 p.378: "This makes the Promises nicer to read and look a lot like synchronous (non-concurrent) code.").

```js
function orderFood(menu) {
  return new Promise(resolve => {
    setTimeout(() => resolve(`${menu} 나왔습니다`), 1000);
  });
}

async function lunch() {
  console.log("주문합니다");
  const food = await orderFood("짜장면");   // 여기서 기다림
  console.log(food);
  console.log("맛있게 먹습니다");
}

lunch();
console.log("주문하고 기다리는 동안 다른 일");
```

결과:

```
주문합니다
주문하고 기다리는 동안 다른 일
짜장면 나왔습니다
맛있게 먹습니다
```

| 낱말 | 뜻 |
|---|---|
| `async` | 함수 앞에 붙여 "이 함수 안에서 `await`를 쓸 거야"라고 알림 |
| `await` | Promise 앞에 붙여 "**결과가 나올 때까지 이 함수 안에서는 기다려**" |

MDN *await*: "The `await` operator is used to wait for a Promise and get its fulfillment value. It can only be used inside an async function or at the top level of a module."

### 4.2 "기다린다"는 것의 정확한 뜻

결과를 다시 보세요. `await`에서 **`lunch` 함수 안의 다음 줄**은 1초를 기다렸지만, **`lunch` 바깥의** `console.log("주문하고 기다리는 동안 다른 일")`은 기다리지 않고 먼저 실행됐습니다.

`await`는 **그 함수만 잠깐 멈추고**, 프로그램 전체를 멈추지는 않습니다. MDN *async function*: "Await expressions make promise-returning functions behave as though they're synchronous by suspending execution until the returned promise is fulfilled or rejected." 진동벨을 든 **손님(`lunch`)만** 기다리고, 식당(프로그램)은 계속 돌아가는 것입니다 (판단).

### 4.3 `async` 함수는 항상 Promise를 돌려준다

```js
async function getNumber() {
  return 7;
}

console.log(getNumber());   // Promise { 7 }  ← 7이 아니라 Promise!
```

MDN: "Async functions always return a promise." 그래서 `async` 함수의 결과를 쓰려면 다시 `await`하거나 `.then`을 붙여야 합니다.

```js
async function main() {
  const n = await getNumber();
  console.log(n);   // 7
}
main();
```

### 4.4 진짜로 쓰는 모습: `fetch`

앱에서 가장 많이 쓰는 비동기 함수는 인터넷에서 데이터를 받아 오는 **`fetch`** 입니다. MDN: "The `fetch()` function returns a Promise which is fulfilled with a `Response` object representing the server's response." [[React Native]] 앱에서도 같은 `fetch`를 씁니다 (판단).

MDN의 예를 그대로 옮깁니다 (주소는 예시이므로 실행해도 실제 데이터가 오지 않을 수 있습니다).

```js
async function getData() {
  const url = "https://example.org/products.json";
  try {
    const response = await fetch(url);
    if (!response.ok) {
      throw new Error(`Response status: ${response.status}`);
    }
    const result = await response.json();
    console.log(result);
  } catch (error) {
    console.error(error.message);
  }
}
```

지금은 모양만 눈에 익혀 두세요. `await fetch(…)`로 응답을 기다리고, `await response.json()`으로 그 안의 데이터를 꺼냅니다. `try...catch`는 다음 절에서 봅니다.

## 5. 실패 처리: `try...catch`

`await`한 Promise가 **실패**하면, 그 자리에서 에러가 던져집니다. MDN *await*: "If the promise is rejected, the `await` expression throws the rejected value." 이 에러는 **`try...catch`** 로 잡습니다.

```js
function checker(val) {
  return new Promise((resolve, reject) => {
    if (val > 5) {
      resolve("Ready");
    } else {
      reject(new Error("Oh no"));
    }
  });
}

async function run() {
  try {
    const msg = await checker(10);
    console.log(msg);                  // Ready
    const msg2 = await checker(3);     // 여기서 실패 → catch로 이동
    console.log(msg2);                 // 실행되지 않음
  } catch (err) {
    console.log("에러 잡음:", err.message);   // 에러 잡음: Oh no
  } finally {
    console.log("done");                     // 성공하든 실패하든 실행
  }
}

run();
```

(`checker`는 입문서 퀴즈 2번(p.385)의 함수입니다.)

| 부분 | 뜻 |
|---|---|
| `try { }` | 일단 해 볼 코드 |
| `catch (err) { }` | `try` 안에서 에러가 나면 여기로 옴. `err`에 에러가 들어 있음 |
| `finally { }` | 성공하든 실패하든 마지막에 항상 실행 (생략 가능) |

`.then`/`.catch`와 `async`/`await` + `try...catch`는 같은 일을 하는 두 가지 방법입니다.

| `.then` 방식 | `async`/`await` 방식 |
|---|---|
| `promise.then(v => …)` | `const v = await promise;` |
| `.catch(e => …)` | `try { … } catch (e) { … }` |

이 시리즈와 앞으로 볼 React 코드에서는 **`async`/`await` 방식**을 주로 씁니다. 읽는 순서와 실행 순서가 같아서 이해하기 쉽기 때문입니다 (판단).

## 6. 이벤트 루프: 혼자서 어떻게 여러 일을?

### 6.1 JavaScript는 한 번에 한 가지 일만 한다

JavaScript는 **한 번에 한 줄씩**, 한 가지 일만 처리합니다. MDN *Execution model*: "An agent is a thread, which means the interpreter can only process one statement at a time." 입문서도 JavaScript는 **단일 스레드**(single-threaded) 언어라고 설명합니다 (p.380).

그런데 어떻게 1초를 기다리는 동안 다른 일을 할 수 있을까요? 기다리는 일을 **다른 곳에 맡기기** 때문입니다 (입문서 p.380: "it doesn't mean that it cannot outsource some tasks and wait for them to come back").

### 6.2 간단한 그림

```
 ┌──────────────┐   맡기기    ┌────────────────────┐
 │  지금 하는 일 │ ─────────▶ │ 타이머, 네트워크 등  │
 │ (콜 스택)     │            │ (브라우저/앱이 처리) │
 └──────▲───────┘            └─────────┬──────────┘
        │ 지금 하는 일이 다 끝나면           │ 다 되면
        │ 하나 꺼내 실행                     ▼
        │                       ┌────────────────────┐
        └────── 이벤트 루프 ◀─── │ 대기 줄 (큐)         │
                                └────────────────────┘
```

1. `setTimeout`이나 `fetch`처럼 기다려야 하는 일은 **브라우저(또는 앱)에 맡깁니다** (입문서 p.382).
2. JavaScript는 기다리지 않고 **지금 할 일을 계속** 합니다.
3. 맡긴 일이 끝나면, 그 뒤에 실행할 함수(콜백)가 **대기 줄**에 섭니다.
4. **지금 하던 일이 모두 끝나면**, 대기 줄에서 하나씩 꺼내 실행합니다. 이 "꺼내 오는" 역할을 하는 것이 **이벤트 루프**(event loop)입니다.

MDN *Execution model*: "Every time, the agent pulls a job from the queue and executes it." / "A job is considered completed when the stack is empty; then, the next job is pulled from the queue."

2.2절에서 0초짜리 `setTimeout`이 `9`보다 늦게 나온 이유가 바로 4번입니다. 콜백이 대기 줄에 바로 섰더라도, **지금 하던 일**(`console.log(4 + 5)`까지)이 끝나야 차례가 옵니다 (입문서 p.384).

> 이벤트 루프의 자세한 동작(대기 줄이 여러 종류인 것 등)은 시리즈를 마친 뒤 [[JavaScript Event Loop and Asynchronous Patterns]]에서 볼 수 있습니다.

## 7. 정리

| 낱말 | 뜻 |
|---|---|
| 동기 | 앞 일이 끝날 때까지 기다렸다가 다음 일을 함 |
| 비동기 | 기다려야 하는 일은 맡겨 두고 다음 일을 먼저 함 |
| 콜백 지옥 | 콜백 안에 콜백이 계속 들어가 들여쓰기가 깊어지는 것 |
| Promise | "나중에 결과를 줄게"라는 약속 객체. pending / fulfilled / rejected |
| `resolve` / `reject` | Promise를 성공 / 실패로 끝내는 함수 |
| `.then` / `.catch` | 성공 결과 / 실패 이유를 받아 처리 |
| `async` | 함수 안에서 `await`를 쓰겠다는 표시. 항상 Promise를 돌려줌 |
| `await` | Promise 결과가 나올 때까지 **그 함수만** 기다림 |
| `try...catch...finally` | 에러가 나면 `catch`로, 항상 `finally` 실행 |
| `fetch` | 인터넷에서 데이터를 받아 오는, Promise를 돌려주는 함수 |
| 이벤트 루프 | 지금 하는 일이 끝나면 대기 줄의 일을 하나씩 꺼내 실행하는 장치 |

---

## 8. 자주 하는 실수

| 잘못 쓴 코드 | 결과 | 무엇이 문제인가 |
|---|---|---|
| `const food = orderFood("짬뽕"); console.log(food);` (await 없이) | `Promise { <pending> }` | 결과가 아니라 **진동벨**(Promise)을 출력했습니다. `await`를 붙입니다 (입문서 p.378에도 같은 결과가 나옴). |
| `async` 없는 함수 안에서 `await` | `SyntaxError: await is only valid in async functions and the top level bodies of modules` | 함수 앞에 `async`를 붙입니다. |
| `async` 함수의 결과를 바로 숫자처럼 씀 | `Promise { 7 }` | `async` 함수는 항상 Promise를 돌려줍니다. `await`하거나 `.then`. |
| `setTimeout(…, 0)`이 바로 실행될 거라 생각 | 지금 하던 일이 다 끝난 뒤 실행 | 6.2절의 4번. |
| 실패할 수 있는 `await`에 `try...catch`가 없음 | 에러가 잡히지 않음 (Node.js는 에러를 출력하고 종료) | `fetch` 같은 네트워크 작업은 실패할 수 있으니 `try...catch`로 감쌉니다. |

## 9. 확인 퀴즈

**Q1.** 아래 코드의 출력 순서는?
```js
console.log("A");
setTimeout(() => console.log("B"), 1000);
console.log("C");
```

> [!question]- 정답 보기
> `A`, `C`, `B`입니다. `setTimeout`은 예약만 하고 바로 다음 줄로 넘어갑니다.

**Q2.** Promise의 세 가지 상태를 말해 보세요.

> [!question]- 정답 보기
> pending(대기), fulfilled(성공), rejected(실패)입니다.

**Q3.** 입문서 퀴즈 1번입니다 (p.385). 아래 코드가 에러를 내는 이유와 고치는 법은?
```js
function addOne(val) {
  return val + 1;
}
function total(a, b, callback) {
  const sum = a + b;
  return callback(sum);
}
console.log(total(4, 5, addOne()));
```

> [!question]- 정답 보기
> `addOne()`처럼 괄호를 붙이면 함수를 먼저 실행해서 그 결과(`NaN`)를 넘깁니다. `total` 안에서 `callback(sum)`을 부를 때 함수가 아니라서 `TypeError: callback is not a function`이 납니다. `total(4, 5, addOne)`로 괄호를 빼면 `10`이 나옵니다 ([[JS 첫걸음 07 - 함수|레슨 07]]의 콜백 실수와 같음).

**Q4.** 아래 코드는 무엇을 출력할까요?
```js
async function getNumber() {
  return 7;
}
console.log(getNumber());
```

> [!question]- 정답 보기
> `Promise { 7 }`입니다 (Node.js 기준 모양). `async` 함수는 항상 Promise를 돌려줍니다. `7`을 꺼내려면 `await getNumber()`나 `getNumber().then(...)`을 씁니다.

**Q5.** 아래 `.then` 코드를 `async`/`await`로 바꿔 보세요.
```js
orderFood("짜장면").then(food => console.log(food));
```

> [!question]- 정답 보기
> ```js
> async function eat() {
>   const food = await orderFood("짜장면");
>   console.log(food);
> }
> eat();
> ```

**Q6.** 0.3초마다 3, 2, 1을 출력하고 "발사!"를 출력하는 카운트다운을 만들어 보세요. 아래 `wait` 함수를 쓰세요.
```js
function wait(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}
```

> [!question]- 예시 답안
> ```js
> async function countdown() {
>   for (let i = 3; i >= 1; i--) {
>     console.log(i);
>     await wait(300);
>   }
>   console.log("발사!");
> }
> countdown();
> ```
> 반복문 안의 `await`가 매번 0.3초씩 `countdown` 함수를 멈춥니다.

**Q7.** 입문서 퀴즈 4번입니다 (p.385). 아래 함수가 Promise를 돌려주도록 고치세요.
```js
function myFun() {
  return "Hello";
}
myFun().then(val => console.log(val));
```

> [!question]- 정답 보기
> 함수 앞에 `async`를 붙입니다.
> ```js
> async function myFun() {
>   return "Hello";
> }
> myFun().then(val => console.log(val));   // Hello
> ```
