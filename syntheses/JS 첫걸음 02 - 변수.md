# JS 첫걸음 02 - 변수

1. **변수**가 무엇이고 왜 필요한지

## 1. 변수란?

### 비유로 이해하기: 이름표 붙은 상자

책상 위에 상자가 하나 있고, 겉에 **"사과 개수"** 라는 이름표가 붙어 있다고 해 봅시다. 상자 안에는 쪽지가 들어 있고, 쪽지에는 `3`이라고 적혀 있습니다.

- 누가 "사과 개수가 몇 개야?"라고 물으면, 이름표를 보고 상자를 열어 `3`이라고 답합니다.
- 사과를 2개 더 사 오면, 쪽지를 꺼내 `5`로 바꿔 넣습니다. 상자와 이름표는 그대로입니다.

**변수(variable)** 가 바로 이 상자입니다. **값에 이름을 붙여 보관해 두는 것**입니다. MDN은 이렇게 설명합니다: "You use variables as symbolic names for values in your application." (*Grammar and types*)

### 변수가 왜 필요할까요?

입문서는 이렇게 말합니다 (p.43). 변수가 없으면 코드는 **실행할 때마다 똑같은 일만** 합니다. 변수를 쓰면 실행할 때마다 **다른 값으로 다른 일을** 하게 만들 수 있습니다.

예를 들어 게임 점수를 생각해 봅시다. 점수는 게임을 할 때마다, 아니 게임 도중에도 계속 바뀝니다. "점수"라는 상자를 하나 만들어 두고, 그 안의 숫자만 계속 바꾸는 것입니다.

## 2. `let`으로 변수 만들기

### 2.1 만들기 (선언)

```js
let appleCount = 3;
```

이 한 줄은 세 부분으로 되어 있습니다 (입문서 p.44).

| 부분 | 코드 | 뜻 |
|---|---|---|
| ① 만들겠다는 표시 | `let` | "새 상자를 하나 만들게요" |
| ② 이름 | `appleCount` | 상자에 붙일 이름표 |
| ③ 처음 넣을 값 | `= 3` | 상자에 처음 넣을 쪽지 |

변수를 **처음 만드는 것**을 **선언(declare)** 한다고 합니다. 선언할 때는 반드시 `let`이나 `const` 같은 특별한 낱말을 앞에 붙입니다 (입문서 p.43).

### 2.2 꺼내 보기

이름만 쓰면 상자 안의 값을 꺼내 쓸 수 있습니다.

```js
let appleCount = 3;
console.log(appleCount);
```

결과:

```
3
```

`console.log("appleCount")`처럼 따옴표를 붙이면 안 됩니다. 그러면 상자 안의 값이 아니라 `appleCount`라는 **글자**가 그대로 나옵니다 ([[JS 첫걸음 01 - 프로그램과 콘솔|레슨 01]]에서 본 것과 같습니다).

### 2.3 값 바꾸기

이미 만든 상자의 값을 바꿀 때는 **`let`을 다시 쓰지 않고 이름만** 씁니다 (입문서 p.43).

```js
let appleCount = 3;   // 상자를 만들고 3을 넣는다
appleCount = 5;       // 같은 상자에 5를 넣는다 (let 없음!)
console.log(appleCount);
```

결과:

```
5
```

### 2.4 `=`는 "같다"가 아니라 "넣는다"

수학 시간의 `=`는 "양쪽이 같다"는 뜻이었습니다. JavaScript의 `=`는 다릅니다. **오른쪽 값을 왼쪽 상자에 넣으라**는 명령입니다. MDN: "The assignment (`=`) operator is used to assign a value to a variable or property." 이 동작을 **대입(assign)** 이라고 합니다.

그래서 수학에서는 말이 안 되는 이런 코드도 JavaScript에서는 자연스럽습니다.

```js
let appleCount = 5;
appleCount = appleCount + 1;
console.log(appleCount);
```

결과:

```
6
```

순서대로 읽어 봅니다.
1. 오른쪽 `appleCount + 1`을 먼저 계산합니다. 상자 안의 `5`에 1을 더해 `6`이 됩니다.
2. 그 `6`을 왼쪽 상자 `appleCount`에 넣습니다.

> 양쪽이 같은지 **비교**하는 기호는 따로 있습니다 (`===`). 레슨 04에서 배웁니다.

### 2.5 값 없이 만들기

값을 나중에 넣을 거라면 `let`으로 상자만 먼저 만들 수 있습니다.

```js
let myName;
console.log(myName);
```

결과:

```
undefined
```

**`undefined`** 는 "아직 아무것도 들어 있지 않다"는 뜻의 특별한 값입니다. MDN: "If a variable is declared without an initializer, it is assigned the value `undefined`." (*Grammar and types*) 레슨 03에서 다시 만납니다.

## 3. `const`로 바뀌지 않는 값 만들기

### 비유로 이해하기: 뚜껑을 붙여 버린 상자

어떤 값은 한번 정하면 바뀔 일이 없습니다. 내가 태어난 해, 원주율(3.14159...) 같은 것입니다. 이런 값은 **`const`** 로 만듭니다 (입문서 p.44). `const`는 "constant(변하지 않는)"의 줄임말입니다.

```js
const birthYear = 2015;
console.log(birthYear);   // 2015
```

`const`로 만든 상자는 **뚜껑을 접착제로 붙여 버린 상자**와 같습니다. 처음 넣은 값을 다른 값으로 바꾸려고 하면 에러가 납니다.

```js
const birthYear = 2015;
birthYear = 2016;
```

결과:

```
TypeError: Assignment to constant variable.
```

"상수(constant) 변수에 값을 넣으려(assignment) 했다"는 뜻입니다 (입문서 p.44에도 같은 에러가 나옵니다).

### `const`는 만들 때 꼭 값을 넣어야 합니다

뚜껑을 붙이기 전에 쪽지를 넣어야겠죠. 값 없이 `const`를 만들면 에러가 납니다. MDN: "An initializer for a constant is required."

```js
const pi;
```

결과:

```
SyntaxError: Missing initializer in const declaration
```

### `let`과 `const` 중 무엇을 쓸까?

| | `let` | `const` |
|---|---|---|
| 나중에 값을 바꿀 수 있나? | ✅ 바꿀 수 있음 | ❌ 바꿀 수 없음 |
| 만들 때 값을 꼭 넣어야 하나? | 아니요 (`undefined`로 시작) | 예 |
| 어울리는 값 | 점수, 남은 시간, 장바구니 개수 | 생일, 원주율, 앱 이름 |

- 입문서는 "대부분의 경우 `let`을 쓰라"고 하며 예제도 거의 `let`으로 씁니다 (p.44).
- 이 시리즈에서는 **값이 바뀔 일이 없으면 `const`, 바뀌어야 하면 `let`** 으로 고르겠습니다. `const`로 만들어 두면, 실수로 값을 바꾸는 코드를 썼을 때 엔진이 바로 에러로 알려 주기 때문입니다 (판단).

> [!note] 미리 보기: `const`인데 안쪽이 바뀌는 경우
> 레슨 09(객체)에서 여러 값을 담는 상자를 배우면, `const`로 만들었는데도 **안에 든 물건 하나하나는 바꿀 수 있는** 경우를 보게 됩니다. MDN: "It does not mean the value it holds is immutable — just that the variable identifier cannot be reassigned." 지금은 "`const`는 상자 자체를 **다른 것으로 바꿔 끼울 수 없다**"는 것만 기억하면 됩니다.

## 4. 변수 이름 짓기

### 4.1 꼭 지켜야 하는 규칙 (안 지키면 에러)

| 규칙 | 예 | 결과 |
|---|---|---|
| 글자, `_`, `$`로 시작한다. **숫자로 시작할 수 없다** | `let 2ndPlace = "은메달";` | `SyntaxError: Invalid or unexpected token` |
| **띄어쓰기를 넣을 수 없다** | `let my name = "철수";` | `SyntaxError: Unexpected identifier 'name'` |
| **대문자와 소문자를 다르게 본다** | `appleCount`와 `applecount` | 서로 다른 이름 |
| `if`, `const`처럼 JavaScript가 이미 쓰고 있는 특별한 낱말(**예약어**)은 이름으로 쓸 수 없다 | `let if = 1;` | `SyntaxError: Unexpected token 'if'` |

- 첫 번째 규칙의 근거: MDN, "A JavaScript identifier usually starts with a letter, underscore (`_`), or dollar sign (`$`)." 그리고 "Identifiers are not allowed to start with numbers." (*Lexical grammar*)
- 두 번째 규칙의 근거: 입문서, "Variables cannot contain spaces, but they can use underscores." (p.45)
- 세 번째 규칙의 근거: MDN, "JavaScript is case-sensitive"
- 네 번째 규칙의 근거: MDN, "These keywords cannot be used as identifiers for variables, functions, classes, etc. anywhere in JavaScript source." (*Lexical grammar*, Reserved words)

### 4.2 지키면 좋은 약속 (관례)

에러는 나지 않지만, 다들 이렇게 씁니다 (입문서 p.45).

1. **소문자로 시작합니다.**
2. **무엇이 들어 있는지 알 수 있게 짓습니다.** 나이를 담는다면 `x`가 아니라 `age`라고 짓습니다. 나중에 코드를 다시 읽을 때 바로 알아볼 수 있습니다.
3. **여러 낱말은 붙여 쓰고, 두 번째 낱말부터 첫 글자를 대문자로 씁니다.** 예: `ageOfBuyer`, `appleCount`. 낙타 등의 혹처럼 보인다고 해서 **카멜 케이스(camelCase)** 라고 부릅니다.

> [!tip] 한글 이름도 되나요?
> `let 사과 = 1;`도 실제로 동작합니다. 하지만 대부분의 코드와 라이브러리가 영어 이름을 쓰기 때문에, 이 시리즈에서도 **이름은 영어로, 설명은 한글 주석으로** 씁니다 (판단).

## 5. 옛날 방식 `var`

오래된 코드나 책에서는 `let` 대신 **`var`** 를 자주 봅니다. `var`도 변수를 만드는 낱말이지만, 이 시리즈에서는 쓰지 않습니다. 두 가지 이유가 있습니다.

**이유 1. 같은 이름으로 또 만들어도 에러가 나지 않습니다.**

```js
let appleCount = 3;
let appleCount = 5;   // 실수로 같은 이름의 상자를 또 만듦
```

결과:

```
SyntaxError: Identifier 'appleCount' has already been declared
```

`let`은 이런 실수를 바로 알려 줍니다. `var`는 알려 주지 않습니다. MDN: "Duplicate variable declarations using `var` will not trigger an error". 실수가 조용히 숨어 버리는 것입니다.

**이유 2. 중괄호 `{ }`로 만든 울타리를 무시합니다.**

`let`으로 만든 변수는 자기가 만들어진 `{ }` 안에서만 보입니다. 이것을 **블록 스코프(block scope)** 라고 합니다. **블록(block)** 은 `{`로 시작해 `}`로 끝나는 덩어리이고, **스코프(scope)** 는 그 변수가 보이는 범위입니다 (입문서 p.44).

```js
{
  let insideBox = "안";
}
console.log(insideBox);
```

결과:

```
ReferenceError: insideBox is not defined
```

`var`로 만들면 울타리 밖에서도 보입니다.

```js
{
  var oldStyle = "var로 만든 상자";
}
console.log(oldStyle);
```

결과:

```
var로 만든 상자
```

변수가 보이는 범위가 넓을수록, 엉뚱한 곳에서 실수로 값을 바꿀 위험도 커집니다. 스코프는 레슨 10에서 자세히 배웁니다.

## 6. 정리

| 낱말 | 뜻 |
|---|---|
| 변수 | 값에 이름을 붙여 보관하는 상자 |
| 선언 | 변수를 처음 만드는 것 (`let`, `const`) |
| 대입 | `=`로 오른쪽 값을 왼쪽 변수에 넣는 것 |
| `let` | 나중에 값을 바꿀 수 있는 변수 |
| `const` | 처음 값을 바꿀 수 없는 변수. 만들 때 값을 꼭 넣어야 함 |
| `undefined` | "아직 아무것도 들어 있지 않음"을 나타내는 값 |
| 카멜 케이스 | `appleCount`처럼 두 번째 낱말부터 첫 글자를 대문자로 쓰는 이름 짓기 방식 |
| 블록 스코프 | `let`·`const` 변수는 자기가 만들어진 `{ }` 안에서만 보임 |

## 7. 자주 하는 실수

| 잘못 쓴 코드 | 나오는 에러 | 무엇이 문제인가 |
|---|---|---|
| `let appleCount = 3;` 다음에 `let appleCount = 5;` | `SyntaxError: Identifier 'appleCount' has already been declared` | 값을 바꿀 때는 `let` 없이 `appleCount = 5;`라고 씁니다. |
| `let appleCount = 3;` 다음에 `console.log(applecount);` | `ReferenceError: applecount is not defined` | 대소문자가 다릅니다 (`C`와 `c`). |
| `console.log(score);` 다음에 `let score = 100;` | `ReferenceError: Cannot access 'score' before initialization` | 상자를 만들기 **전에** 열어 보려 했습니다. 아래 설명을 보세요. |
| `const birthYear = 2015;` 다음에 `birthYear = 2016;` | `TypeError: Assignment to constant variable.` | `const` 변수는 값을 바꿀 수 없습니다. 바꿔야 하는 값이면 `let`으로 만듭니다. |
| `const pi;` | `SyntaxError: Missing initializer in const declaration` | `const`는 만들 때 값을 넣어야 합니다. |

> [!note] "만들기 전에 열어 보면" 생기는 일
> 위 표의 세 번째 실수에서 에러 메시지가 `is not defined`(그런 이름 없음)가 아니라 `before initialization`(준비되기 전)인 데에 주목하세요. 엔진은 코드를 실행하기 전에 이미 `score`라는 상자가 **곧 만들어질 것**을 알고 있습니다. 다만 `let score = 100;` 줄에 도착하기 전까지는 그 상자를 쓰지 못하게 막아 둡니다.
> 이 "막혀 있는 구간"을 **TDZ**(Temporal Dead Zone, 일시적 사각지대)라고 부릅니다. MDN: "A variable declared with `let`, `const`, or `class` is said to be in a "temporal dead zone" (TDZ) from the start of the block until code execution reaches the place where the variable is declared and initialized."
> 지금은 **"변수는 만든 다음에 쓴다"** 만 지키면 됩니다. 더 깊은 내용은 시리즈를 마친 뒤 [[JavaScript Core Syntax and Modern ES6+ Fundamentals]] 1.3절에서 볼 수 있습니다.

> [!warning] 콘솔에서는 결과가 다를 수 있어요
> Chrome 콘솔에서 `let appleCount = 3;`과 `let appleCount = 5;`를 **따로따로** 입력하면 에러가 나지 않습니다. Chrome 개발자 도구가 연습하기 편하도록 일부러 허용해 주기 때문입니다 ("The Console now supports redeclarations of let and class statements.", Chrome DevTools 80 릴리스 노트). 파일로 저장한 실제 코드에서는 에러가 납니다. 위 표의 결과를 직접 보고 싶다면 두 줄을 `Shift` + `Enter`로 이어서 **한 번에** 실행해 보세요.

## 8. 확인 퀴즈

**Q1.** 아래 코드가 끝나면 `score`에는 무엇이 들어 있을까요?
```js
let score = 10;
score = score + 5;
score = score + 5;
```

> [!question]- 정답 보기
> `20`입니다. `10` → `15` → `20` 순서로 바뀝니다. `=`는 오른쪽을 먼저 계산해서 왼쪽 상자에 넣습니다.

**Q2.** 다음 중 바꿀 일이 없어서 `const`로 만드는 것이 어울리는 값은 무엇일까요?
① 게임 남은 목숨 ② 앱 이름 ③ 장바구니에 담은 물건 개수

> [!question]- 정답 보기
> ② 앱 이름입니다. ①과 ③은 앱을 쓰는 동안 계속 바뀌므로 `let`으로 만듭니다.

**Q3.** 다음 변수 이름 중 **에러가 나는 것**을 모두 고르세요.
① `userName` ② `user name` ③ `1stPrize` ④ `_count` ⑤ `$price`

> [!question]- 정답 보기
> ②와 ③입니다. ②는 띄어쓰기가 들어 있고, ③은 숫자로 시작합니다. ④와 ⑤처럼 `_`나 `$`로 시작하는 것은 괜찮습니다.

**Q4.** 아래 코드를 실행하면 무엇이 나올까요?
```js
let favoriteFood;
console.log(favoriteFood);
```

> [!question]- 정답 보기
> `undefined`가 나옵니다. 상자는 만들었지만 아직 아무 값도 넣지 않았기 때문입니다.

**Q5.** 친구가 아래 코드에서 에러가 난다고 합니다. 어떻게 고쳐야 할까요?
```js
const level = 1;
level = 2;
```

> [!question]- 정답 보기
> `level`은 게임을 하면서 바뀌는 값이므로 `const` 대신 `let`으로 만들어야 합니다.
> ```js
> let level = 1;
> level = 2;
> ```

**Q6. (직접 해 보기)** 콘솔에서 다음을 해 보세요.
1. `myAge`라는 변수를 `let`으로 만들고 자기 나이를 넣습니다.
2. 1년이 지났다고 치고, `myAge`에 1을 더한 값을 다시 `myAge`에 넣습니다.
3. `console.log`로 `myAge`를 출력합니다.

> [!question]- 예시 답안
> ```js
> let myAge = 12;
> myAge = myAge + 1;
> console.log(myAge);   // 13
> ```
