# JS 첫걸음 03 - 자료형

> **이전**: [[JS 첫걸음 02 - 변수|02 변수]] · **다음**: [[JS 첫걸음 04 - 연산자|04 연산자]] · **목록**: [[JS 첫걸음 00 - 로드맵|로드맵]]

## 이 레슨에서 배우는 것

1. **자료형**이 무엇인지, JavaScript에는 어떤 자료형이 있는지
2. 가장 많이 쓰는 다섯 가지: **문자열, 숫자, 불리언, `undefined`, `null`**
3. `typeof`로 값의 종류를 알아내는 법
4. 자료형을 바꾸는 법, 그리고 JavaScript가 **몰래** 바꿔 버리는 경우

## 1. 자료형이란?

### 비유로 이해하기: 상자에 넣는 물건의 종류

[[JS 첫걸음 02 - 변수|레슨 02]]에서 변수는 이름표 붙은 상자라고 했습니다. 이번에는 **상자 안에 넣는 물건**을 봅니다.

- 이름이나 문장처럼 **글자**를 넣을 수도 있고,
- 나이나 점수처럼 **숫자**를 넣을 수도 있고,
- "불이 켜져 있나?"의 답처럼 **예/아니오**를 넣을 수도 있습니다.

물건의 종류에 따라 할 수 있는 일이 다릅니다. 숫자끼리는 더하거나 곱할 수 있지만, "사과"와 "바나나"를 곱할 수는 없죠. 이렇게 **값의 종류**를 **자료형**(data type, 데이터 타입)이라고 합니다 (입문서 p.45).

### JavaScript가 알아서 종류를 정합니다

JavaScript에서는 변수를 만들 때 "이 상자에는 숫자만 넣을 거야"라고 미리 말하지 않습니다. **넣은 값을 보고 엔진이 알아서 종류를 판단합니다.** `5`를 넣으면 숫자, `"5"`를 넣으면 글자입니다 (입문서 p.45).

그래서 같은 상자에 숫자를 넣었다가 글자로 바꿔 넣어도 됩니다. MDN: "any variable can be assigned (and re-assigned) values of all types" (*JavaScript data types and data structures*).

```js
let box = 5;
console.log(typeof box);   // number
box = "다섯";
console.log(typeof box);   // string
```

`typeof`는 값의 종류를 알려 주는 낱말입니다. 5절에서 자세히 봅니다.

### 기본 자료형 일곱 가지

JavaScript에는 **기본 자료형**(primitive, 원시 자료형)이 일곱 가지 있습니다. 입문서: "JavaScript has seven primitives: String, Number, BigInt, Boolean, Symbol, undefined, and null." (p.45)

| 자료형 | 뜻 | 예 | 이 레슨에서 |
|---|---|---|---|
| **String** (문자열) | 글자 | `"안녕"` | ⭐ 자세히 |
| **Number** (숫자) | 숫자 | `42`, `3.14` | ⭐ 자세히 |
| **Boolean** (불리언) | 참 또는 거짓 | `true`, `false` | ⭐ 자세히 |
| **undefined** | 아직 값이 없음 | `undefined` | ⭐ 자세히 |
| **null** | 비어 있음 | `null` | ⭐ 자세히 |
| **BigInt** | 아주 큰 정수 | `9007199254740993n` | 간단히 |
| **Symbol** | 세상에 하나뿐인 값 | `Symbol("id")` | 간단히 |

일곱 가지 말고 **객체**(Object)라는 자료형도 있습니다. 여러 값을 한꺼번에 담는 큰 상자입니다. 레슨 08(배열), 09(객체)에서 배웁니다 (MDN: "All types except Object define immutable values ... We refer to values of these types as primitive values.").

## 2. 문자열 (String): 글자

**문자열**은 글자를 담는 자료형입니다. 글자들이 줄줄이 이어져 있다고 해서 "문자열(文字列)"입니다 (입문서 p.46: "It is a sequence of characters.").

### 2.1 따옴표 세 가지

문자열은 따옴표로 감싸서 만듭니다. 세 가지 따옴표를 쓸 수 있습니다 (입문서 p.46).

```js
const greeting = "안녕하세요";   // 큰따옴표
const name = '철수';             // 작은따옴표
const message = `반가워요`;      // 백틱 (키보드 숫자 1 왼쪽의 ` 키)
```

큰따옴표와 작은따옴표는 기능이 같습니다. 하나를 골라 **한 가지로 통일해서** 쓰면 됩니다 (입문서 p.46: "consistency is key"). 이 시리즈는 큰따옴표를 씁니다.

### 2.2 따옴표 안에 따옴표를 넣고 싶을 때

문자열은 **여는 따옴표와 같은 따옴표를 다시 만나는 순간 끝납니다** (입문서 p.46). 그래서 이런 코드는 에러가 납니다.

```js
let funActivity = 'Let's learn JavaScript';
```

결과:

```
SyntaxError: Unexpected identifier 's'
```

엔진은 `'Let'`에서 문자열이 끝났다고 생각합니다. 그 뒤의 `s learn JavaScript'`는 무슨 뜻인지 알 수 없어서 에러를 냅니다.

해결 방법은 두 가지입니다.

**방법 1. 바깥 따옴표를 다른 것으로 바꾼다** (입문서 p.46)

```js
console.log("It's me");                      // It's me
console.log('그가 "안녕"이라고 했다');         // 그가 "안녕"이라고 했다
```

**방법 2. 따옴표 앞에 `\`(역슬래시)를 붙인다** (입문서 p.47)

`\`는 "바로 다음 글자를 평소처럼 해석하지 말라"는 표시입니다. 이것을 **이스케이프 문자**(escape character)라고 합니다.

```js
console.log("그가 \"안녕\"이라고 했다");      // 그가 "안녕"이라고 했다
```

`\` 뒤의 `"`는 "문자열 끝"이 아니라 **그냥 따옴표 글자**가 됩니다.

### 2.3 줄 바꾸기: `\n`

`\n`은 "여기서 줄을 바꿔라"라는 뜻입니다 (입문서 p.48). `n`은 new line(새 줄)의 머리글자입니다.

```js
console.log("첫째 줄\n둘째 줄");
```

결과:

```
첫째 줄
둘째 줄
```

`\` 글자 자체를 보여 주고 싶으면 `\\`처럼 두 번 씁니다 (입문서 p.48).

### 2.4 백틱의 특별한 능력: 템플릿 리터럴

백틱(`` ` ``)으로 만든 문자열을 **템플릿 리터럴**(template literal)이라고 부릅니다. 두 가지 특별한 능력이 있습니다.

**능력 1. 문자열 안에 변수를 끼워 넣을 수 있습니다** (입문서 p.47)

`${ }` 안에 변수 이름을 쓰면, 그 자리에 변수의 값이 들어갑니다.

```js
const name = "철수";
const greeting = "안녕하세요";
console.log(`${name}야, ${greeting}!`);
```

결과:

```
철수야, 안녕하세요!
```

`${ }` 안에는 변수뿐 아니라 계산식도 넣을 수 있습니다 (MDN: "placeholders of the form `${expression}`").

```js
const age = 12;
console.log(`내년에는 ${age + 1}살`);   // 내년에는 13살
```

> [!warning] 큰따옴표에서는 안 돼요
> `"${name}야"`처럼 큰따옴표나 작은따옴표 안에 `${ }`를 쓰면, 값이 끼워지지 않고 `${name}야`라는 글자가 그대로 나옵니다. 끼워 넣기는 **백틱에서만** 됩니다.

**능력 2. 여러 줄을 그대로 쓸 수 있습니다** (MDN: "Any newline characters inserted in the source are part of the template literal.")

```js
const poem = `하늘
바다`;
console.log(poem);
```

결과:

```
하늘
바다
```

### 2.5 문자열 이어 붙이기: `+`

문자열끼리 `+`로 연결하면 **이어 붙여집니다** (입문서 p.57).

```js
console.log("사과" + "나무");   // 사과나무
console.log("3" + "4");         // 34  ← 숫자 덧셈이 아니에요!
```

두 번째 줄을 보세요. `"3"`과 `"4"`는 따옴표 안에 있으므로 **숫자가 아니라 글자**입니다. 그래서 7이 아니라 `34`가 됩니다. 이 차이는 6절에서 다시 중요해집니다.

## 3. 숫자 (Number)

### 3.1 정수와 소수가 한 종류

많은 프로그래밍 언어는 정수(1, 2, 3)와 소수(1.5)를 다른 자료형으로 나눕니다. JavaScript는 **모든 숫자를 `number` 하나로** 다룹니다 (입문서 p.48).

```js
console.log(7);      // 7
console.log(-3);     // -3
console.log(3.14);   // 3.14
console.log(10 / 4); // 2.5
```

### 3.2 너무 큰 정수는 정확하지 않아요

`number`로 **정확하게** 다룰 수 있는 정수에는 한계가 있습니다. 가장 큰 값은 `9007199254740991`(약 9천조)입니다. MDN: "it can only safely store integers in the range -(2^53 − 1) (Number.MIN_SAFE_INTEGER) to 2^53 − 1 (Number.MAX_SAFE_INTEGER)."

```js
console.log(Number.MAX_SAFE_INTEGER);   // 9007199254740991
console.log(9007199254740992 + 1);      // 9007199254740992  ← 1을 더했는데 그대로!
```

이 범위를 넘으면 숫자가 "대충 비슷한 값"으로 바뀌어 버립니다 (MDN: "they will instead be represented by a double-precision floating point approximation"). 평소에 쓰는 점수, 나이, 가격은 이 범위 안이라 걱정하지 않아도 됩니다.

### 3.3 `NaN`: 숫자가 아닌 숫자

숫자로 바꿀 수 없는 것을 숫자로 바꾸려고 하면 **`NaN`** 이 나옵니다 (입문서 p.55–56). `NaN`은 "Not a Number(숫자가 아님)"의 줄임말입니다 (MDN: "The `NaN` global property is a value representing Not-A-Number.").

```js
console.log(Number("열두"));   // NaN
console.log(typeof NaN);       // number  ← 이름은 "숫자 아님"인데 종류는 number!
```

이상해 보이지만, `NaN`은 "**숫자 계산을 하다가 실패했다**"는 뜻의 특별한 숫자 값이라고 이해하면 됩니다 (판단). 어떤 값이 `NaN`인지 확인할 때는 `Number.isNaN()`을 씁니다 (MDN).

```js
console.log(Number.isNaN(Number("열두")));   // true
```

## 4. 나머지 기본 자료형

### 4.1 불리언 (Boolean): 예 또는 아니오

**불리언**은 값이 딱 두 개뿐입니다. **`true`**(참, 예)와 **`false`**(거짓, 아니오). 그 중간은 없습니다 (입문서 p.50).

```js
const isRaining = true;      // 비가 오나? → 예
const hasHomework = false;   // 숙제가 있나? → 아니오
```

전등 스위치처럼 켜짐/꺼짐, 예/아니오를 나타낼 때 씁니다 (입문서 p.50: "which can indicate on/off or yes/no"). 이름도 `isRaining`, `hasHomework`처럼 **예/아니오로 답할 수 있는 질문 모양**으로 지으면 읽기 쉽습니다 (판단, 입문서 예시 `lightIsOn`, `objectIsDeleted` 참고).

비교를 하면 그 결과로 불리언이 나옵니다. 레슨 04(연산자)와 05(조건문)에서 아주 많이 씁니다.

```js
console.log(5 > 3);    // true
console.log(2 > 10);   // false
```

### 4.2 `undefined`와 `null`: 두 종류의 "없음"

둘 다 "값이 없다"는 뜻이지만 쓰임이 다릅니다.

| | `undefined` | `null` |
|---|---|---|
| 누가 넣나? | **엔진이** 자동으로 | **내가** 직접 |
| 언제? | 변수를 만들고 아무것도 안 넣었을 때 | "지금은 비어 있음"을 일부러 표시할 때 |
| 비유 (판단) | 아직 아무도 열어 보지 않은 빈 상자 | "비어 있음" 쪽지를 일부러 넣어 둔 상자 |

```js
let homework;          // 아무것도 안 넣음
console.log(homework); // undefined

let pet = null;        // "애완동물 없음"을 일부러 표시
console.log(pet);      // null
```

- 입문서는 `undefined`를 **직접 넣지 말라**고 합니다. 비어 있다는 것을 표시하고 싶으면 `null`을 넣는 편이 낫다고 권합니다 (p.51–52: "it is better to assign null to a variable when you want to say it is empty and unknown at first").
- `null`은 반드시 **소문자**로 씁니다 (입문서 p.51).

### 4.3 BigInt: 아주 큰 정수

3.2절의 한계보다 큰 정수가 필요할 때 씁니다. 숫자 끝에 **`n`** 을 붙입니다 (입문서 p.49).

```js
const big = 9007199254740993n;
console.log(big + 1n);      // 9007199254740994n  ← 정확해요
console.log(typeof big);    // bigint
```

BigInt와 보통 숫자는 **섞어서 계산할 수 없습니다** (입문서 p.49).

```js
const big = 10n;
console.log(big + 1);
```

결과:

```
TypeError: Cannot mix BigInt and other types, use explicit conversions
```

처음 공부할 때는 쓸 일이 거의 없습니다. "끝에 `n`이 붙은 숫자는 BigInt" 정도만 알아 두면 됩니다.

### 4.4 Symbol: 세상에 하나뿐인 값

`Symbol("id")`로 만든 값은 **설명이 같아도 서로 다른 값**입니다 (입문서 p.50–51). 주로 객체를 다룰 때 쓰는데, 입문 단계에서는 거의 쓰지 않습니다. 이름만 알아 두면 됩니다.

## 5. `typeof`: 값의 종류 알아내기

`typeof` 뒤에 값이나 변수를 쓰면, 그 **종류의 이름을 문자열로** 알려 줍니다 (입문서 p.53).

```js
console.log(typeof "안녕");        // string
console.log(typeof 42);            // number
console.log(typeof true);          // boolean
console.log(typeof undefined);     // undefined
console.log(typeof 42n);           // bigint
console.log(typeof Symbol("x"));   // symbol
console.log(typeof "42");          // string  ← 따옴표가 있으면 글자!
console.log(typeof null);          // object  ← ⚠️ 이상하죠?
```

### `typeof null`이 `"object"`인 이유

`null`은 분명히 기본 자료형인데 `typeof`는 `"object"`라고 답합니다. 입문서는 이것을 **아주 오래된 버그**라고 설명합니다. 고치면 이미 만들어진 코드가 제대로 동작하지 않게 되는 문제(하위 호환성) 때문에 고칠 수 없다고 합니다 (p.54: "This is a bug that has been there since forever and now cannot be removed due to backward compatibility problems.").

그래서 어떤 값이 `null`인지 확인할 때는 `typeof`를 쓰면 안 됩니다. MDN: "`typeof null` returns `"object"`, so one has to use `=== null` to test for `null`." `===`는 레슨 04에서 배웁니다.

## 6. 자료형 바꾸기

### 6.1 JavaScript가 몰래 바꾸는 경우

자료형이 다른 값끼리 계산하면, 많은 언어는 에러를 냅니다. JavaScript는 에러를 내지 않고 **한쪽의 자료형을 몰래 바꿔서** 계산합니다 (입문서 p.54). MDN: "JavaScript is also a weakly typed language, which means it allows implicit type conversion when an operation involves mismatched types, instead of throwing type errors."

```js
console.log(2 * "2");   // 4
console.log(2 + "2");   // 22
```

- **곱하기 `*`**: 글자 `"2"`를 숫자 `2`로 바꿔서 곱합니다. 결과는 `4`.
- **더하기 `+`**: `+`는 문자열을 이어 붙이는 데도 쓰입니다 (2.5절). 그래서 이번에는 반대로 숫자 `2`를 글자 `"2"`로 바꿔서 **이어 붙입니다**. 결과는 `"22"`.

입문서는 이것을 "위험하다(dangerous)"고 경고합니다 (p.54). 같은 숫자 두 개인데 기호에 따라 결과가 완전히 달라지기 때문입니다.

> [!tip] 실제로 자주 생기는 일
> 사용자가 입력창에 쓴 값은 숫자처럼 보여도 **문자열**인 경우가 많습니다. 입력받은 나이에 1을 더했더니 `13`이 아니라 `121`이 나오는 버그가 바로 이것입니다 (판단).

### 6.2 내가 직접 바꾸기: `String()`, `Number()`, `Boolean()`

몰래 바뀌는 것에 기대지 말고, **직접 바꾸는 것이 안전합니다** (입문서 p.54).

```js
console.log(2 + Number("2"));   // 4  ← 먼저 숫자로 바꿨으니 덧셈
```

| 명령 | 하는 일 | 예 → 결과 |
|---|---|---|
| `String(값)` | 문자열로 바꾼다 | `String(6)` → `"6"` |
| `Number(값)` | 숫자로 바꾼다. 안 되면 `NaN` | `Number("12")` → `12`, `Number("hello")` → `NaN` |
| `Boolean(값)` | 불리언으로 바꾼다 | `Boolean("안녕")` → `true`, `Boolean("")` → `false` |

### 6.3 `Number()`의 헷갈리는 결과

| 바꾸려는 값 | 결과 | 설명 |
|---|---|---|
| `Number("12")` | `12` | 따옴표만 떼면 숫자 |
| `Number(" 42 ")` | `42` | 앞뒤 빈칸은 무시 |
| `Number("12개")` | `NaN` | 숫자 아닌 글자가 섞이면 실패 |
| `Number("hello")` | `NaN` | 숫자로 읽을 수 없음 (입문서 p.56) |
| `Number("")` | `0` | ⚠️ 빈 문자열은 0 (입문서 p.55) |
| `Number(null)` | `0` | ⚠️ `null`도 0 (입문서 p.55) |
| `Number(undefined)` | `NaN` | `undefined`는 NaN |

빈 문자열과 `null`이 `0`이 되는 것은 JavaScript를 만든 사람들의 선택이라서, 그냥 외워 두어야 합니다 (입문서 p.55).

### 6.4 `Boolean()`: 거짓이 되는 값은 몇 개 안 됩니다

`Boolean()`으로 바꾸면 **대부분의 값은 `true`** 가 됩니다. `false`가 되는 값은 정해져 있습니다. 이런 값을 **falsy**(거짓 같은 값)라고 부릅니다. MDN: "A falsy (sometimes written falsey) value is a value that is considered false when encountered in a Boolean context."

꼭 외워 둘 falsy 값 여섯 가지:

| falsy 값 | 뜻 |
|---|---|
| `false` | 거짓 |
| `0` | 숫자 0 |
| `""` | 빈 문자열 (따옴표 사이에 아무것도 없음) |
| `null` | 비어 있음 |
| `undefined` | 아직 값 없음 |
| `NaN` | 숫자 아님 |

(MDN 목록에는 이 밖에 `-0`, `0n`, `document.all`이 더 있습니다. 거의 만날 일이 없습니다.)

**이 여섯 가지가 아니면 전부 `true`** 입니다. 특히 아래 결과에 주의하세요.

```js
console.log(Boolean("false"));   // true   ← 글자 "false"는 빈 문자열이 아니니까!
console.log(Boolean("0"));       // true   ← 글자 "0"도 마찬가지
console.log(Boolean(" "));       // true   ← 빈칸 한 개도 글자
console.log(Boolean(-1));        // true   ← 0이 아닌 숫자는 전부 true
console.log(Boolean(""));        // false
console.log(Boolean(0));         // false
```

`Boolean("false")`가 `true`인 것은 입문서도 짚는 함정입니다 (p.56: "even the string "false"!"). falsy는 레슨 05(조건문)에서 다시 아주 중요하게 쓰입니다.

## 7. 정리

| 낱말 | 뜻 |
|---|---|
| 자료형 | 값의 종류 |
| 기본 자료형 | String, Number, BigInt, Boolean, Symbol, undefined, null (7가지) |
| 문자열 | 따옴표로 감싼 글자. `"..."`, `'...'`, `` `...` `` |
| 이스케이프 문자 | `\`. 다음 글자를 특별하게 해석하라는 표시 (`\"`, `\n`, `\\`) |
| 템플릿 리터럴 | 백틱 문자열. `${ }`로 값을 끼워 넣고 여러 줄을 쓸 수 있음 |
| `NaN` | 숫자로 바꾸지 못했을 때 나오는 "숫자 아님" 값. 종류는 number |
| 불리언 | `true` 또는 `false` |
| `undefined` / `null` | 엔진이 넣는 "아직 없음" / 내가 넣는 "비어 있음" |
| `typeof` | 값의 종류 이름을 알려 줌. `typeof null`은 버그로 `"object"` |
| falsy | `Boolean()`으로 바꾸면 `false`가 되는 값. `false`, `0`, `""`, `null`, `undefined`, `NaN` |

## 8. 자주 하는 실수

| 잘못 쓴 코드 | 결과 | 무엇이 문제인가 |
|---|---|---|
| `'Let's go'` | `SyntaxError: Unexpected identifier 's'` | 작은따옴표 문자열 안에 작은따옴표가 있습니다. `"Let's go"` 또는 `'Let\'s go'`로 씁니다. |
| `"${name}야"` | `${name}야`가 글자 그대로 나옴 | 값 끼워 넣기는 백틱(`` ` ``)에서만 됩니다. |
| `console.log("3" + 4);` | `34` | 문자열과 숫자를 `+`하면 이어 붙여집니다. 숫자 덧셈을 원하면 `Number("3") + 4`. |
| `console.log(10n + 1);` | `TypeError: Cannot mix BigInt and other types, use explicit conversions` | BigInt는 BigInt끼리만 계산합니다. `10n + 1n`. |
| `typeof null`로 `null` 확인하기 | `"object"`가 나옴 | 오래된 버그입니다. `null` 확인은 `=== null`로 합니다 (레슨 04). |
| `Boolean("false")`가 `false`일 거라고 생각 | `true` | 글자 `"false"`는 빈 문자열이 아니므로 `true`입니다. |

## 9. 확인 퀴즈

**Q1.** 각 값의 `typeof` 결과를 말해 보세요. (입문서 연습문제 2.1 변형, p.57)
① `"철수"` ② `1000` ③ `"1000"` ④ `false` ⑤ `undefined` ⑥ `null`

> [!question]- 정답 보기
> ① `string` ② `number` ③ `string` (따옴표가 있으므로 글자) ④ `boolean` ⑤ `undefined` ⑥ `object` (오래된 버그)

**Q2.** 아래 코드는 무엇을 출력할까요?
```js
const fruit = "사과";
const count = 3;
console.log(`${fruit} ${count}개`);
console.log("${fruit} ${count}개");
```

> [!question]- 정답 보기
> 첫 줄은 `사과 3개`, 둘째 줄은 `${fruit} ${count}개`입니다. 큰따옴표 안에서는 `${ }`가 동작하지 않고 글자 그대로 나옵니다.

**Q3.** 다음 세 줄의 결과를 예상해 보세요.
```js
console.log(5 + "5");
console.log(5 * "5");
console.log(5 + Number("5"));
```

> [!question]- 정답 보기
> `55`, `25`, `10`입니다.
> - `+`에 문자열이 있으면 이어 붙이기가 되어 `"55"`.
> - `*`는 이어 붙이기 기능이 없으므로 `"5"`를 숫자로 바꿔 곱해서 `25`.
> - 직접 `Number()`로 바꿨으므로 숫자 덧셈 `10`.

**Q4.** 다음 중 `Boolean()`으로 바꿨을 때 `false`가 되는 것을 모두 고르세요.
① `0` ② `"0"` ③ `""` ④ `" "` ⑤ `null` ⑥ `"false"` ⑦ `NaN`

> [!question]- 정답 보기
> ① `0`, ③ `""`, ⑤ `null`, ⑦ `NaN`입니다. ②, ④, ⑥은 비어 있지 않은 **문자열**이므로 모두 `true`입니다.

**Q5.** `Number("12살")`의 결과는 무엇이고, 그 값의 `typeof`는 무엇일까요?

> [!question]- 정답 보기
> `NaN`이고, `typeof NaN`은 `number`입니다. `"12살"`에 숫자가 아닌 글자 `살`이 섞여 있어서 숫자로 바꾸지 못했습니다.

**Q6. (직접 해 보기)** 콘솔에서 다음을 해 보세요.
1. `myName`에 자기 이름, `myAge`에 나이를 넣습니다.
2. 템플릿 리터럴로 `"제 이름은 ○○이고, 10년 뒤에는 ○○살이에요"`를 출력합니다. 10년 뒤 나이는 `${ }` 안에서 계산합니다.

> [!question]- 예시 답안
> ```js
> const myName = "김코딩";
> const myAge = 12;
> console.log(`제 이름은 ${myName}이고, 10년 뒤에는 ${myAge + 10}살이에요`);
> // 제 이름은 김코딩이고, 10년 뒤에는 22살이에요
> ```
