# 렌더링 첫걸음 10 - 자식이 부모 함수를 부를 때

> **보충 레슨**: [[렌더링 첫걸음 03 - React 첫 만남|03 React 첫 만남]]의 props 다음에 바로 읽어도 됩니다.
> **이전**: [[렌더링 첫걸음 09 - 버튼 하나를 누르면|09 버튼 하나를 누르면]] · **목록**: [[렌더링 첫걸음 00 - 로드맵|로드맵]]

## 이 레슨에서 배우는 것

1. 함수가 **값**이라는 것의 뜻: "넘기기"와 "부르기"의 차이
2. 부모가 자식에게 함수를 넘기고, 자식이 **눌렸을 때** 그 함수를 부르는 흐름
3. 같은 함수에 붙은 **세 개의 이름**(`handleXxx`, `onXxx`, `onPress`) 구별하기
4. 자식이 부모에게 **값을 올려 보내는** 방법
5. 가장 흔한 실수: **괄호**를 붙여 렌더 중에 불러 버리기
6. (심화) 매번 새로 만들어지는 함수, `useCallback`, 오래된 값을 기억하는 함수

> 웹 React 예제는 React 19.3.1 + react-dom + jsdom에서, 순수 JavaScript 예제는 Node.js에서 실행해 결과를 확인했습니다. React Native 예제는 실행 환경이 없어 **실행하지 않았습니다**. RN에서는 웹의 `onClick` 자리에 `onPress`가 들어갈 뿐, 함수를 넘기는 방식은 같습니다 (판단: 둘 다 React의 props이기 때문).

---

## 1. 복습: 함수는 값이다

### 비유로 이해하기: 리모컨과 리모컨 누르기

**리모컨을 건네는 것**과 **리모컨 버튼을 누르는 것**은 다릅니다. 리모컨을 건네받은 사람은 나중에 원할 때 누를 수 있습니다. JavaScript에서 함수 이름만 쓰면 리모컨을 건네는 것이고, 이름 뒤에 `()`를 붙이면 지금 누르는 것입니다.

[[JS 첫걸음 07 - 함수|JS 첫걸음 07]]의 5.1절(함수를 변수에 넣기)과 6절(콜백)에서 본 내용입니다.

### 직접 해 보기 (Node.js에서 실행함)

```js
function sayHi(name) { return `안녕, ${name}`; }

const greet = sayHi;           // 괄호 없음: 함수 자체를 담음
console.log(typeof greet);     // ①
console.log(greet === sayHi);  // ②
console.log(greet('철수'));     // ③

const result = sayHi('영희');  // 괄호 있음: 지금 부르고, 결과를 담음
console.log(typeof result, result); // ④

function doLater(fn) {
  console.log('doLater 시작');
  fn('민수');                  // 받은 함수를 "나중에" 부름
  console.log('doLater 끝');
}
doLater((name) => console.log(`콜백 실행: ${name}`));
```

실행 결과:

```
function
true
안녕, 철수
string 안녕, 영희
doLater 시작
콜백 실행: 민수
doLater 끝
```

- ①② `greet`과 `sayHi`는 **같은 함수**를 가리키는 두 이름입니다.
- ④ `sayHi('영희')`는 그 자리에서 실행되어 **문자열**이 담깁니다.
- `doLater`는 받은 함수를 언제 부를지 **스스로 정합니다**. React의 자식 컴포넌트도 이렇게 합니다.

## 2. 부모 함수를 자식에게 넘기기

### 비유로 이해하기: 초인종

집주인(부모)이 문 앞에 **초인종**(자식)을 달고, 초인종 줄을 **집 안의 벨**(부모의 함수)에 연결해 둡니다. 손님이 초인종을 누르면 소리는 **집 안에서** 납니다. 초인종은 집 안에서 무슨 일이 일어나는지 몰라도 됩니다.

react.dev도 같은 생각을 설명합니다: "Often you'll want the parent component to specify a child's event handler." 그리고 부모는 자식이 그 함수를 어떻게 쓸지 알 필요가 없습니다: "Notice how the `App` component does not need to know *what* `Toolbar` will do with `onPlayMovie` or `onUploadImage`. That's an implementation detail of the `Toolbar`." (*Responding to Events*)

### 2.1 웹 React로 직접 해 보기 (실행함)

```jsx
function TodoItem({ title, onDelete }) {                  // 자식: onDelete라는 "함수"를 받음
  console.log(`  [자식 렌더] ${title}, onDelete 타입 = ${typeof onDelete}`);
  return <button onClick={() => onDelete(title)}>{title} 삭제</button>; // 눌렸을 때 부모 함수를 부름
}

function App() {
  const [items, setItems] = useState(['우유', '빵']);

  function handleDelete(title) {                          // 부모: state를 가진 쪽에 함수를 둠
    console.log(`  [부모 handleDelete 실행] 받은 값 = ${title}`);
    setItems(prev => prev.filter(t => t !== title));
  }

  console.log(`[부모 렌더] items = ${items.join(', ')}`);
  return <div>{items.map(t => <TodoItem key={t} title={t} onDelete={handleDelete} />)}</div>;
}
```

실행 결과:

```
--- 1) 첫 렌더
[부모 렌더] items = 우유, 빵
  [자식 렌더] 우유, onDelete 타입 = function
  [자식 렌더] 빵, onDelete 타입 = function
--- 2) "우유 삭제" 클릭
  [부모 handleDelete 실행] 받은 값 = 우유
[부모 렌더] items = 빵
  [자식 렌더] 빵, onDelete 타입 = function
```

읽는 법:
1. 첫 렌더에서 자식은 함수를 **받기만** 합니다. 아직 아무것도 부르지 않습니다.
2. 클릭하면 자식이 `onDelete('우유')`를 부릅니다. 그런데 실행되는 코드는 **부모의 `handleDelete`** 입니다.
3. 부모의 state가 바뀌었으므로 부모가 다시 렌더하고, 자식도 새 props로 다시 렌더합니다 ([[렌더링 첫걸음 04 - 렌더와 커밋|레슨 04]]).

### 2.2 React Native로 쓰면 (실행하지 않음)

```tsx
import { useState } from 'react';
import { Pressable, Text } from 'react-native';

function TodoItem({ title, onDelete }: { title: string; onDelete: (title: string) => void }) {
  return (
    <Pressable onPress={() => onDelete(title)}>
      <Text>{title} 삭제</Text>
    </Pressable>
  );
}

function TodoList() {
  const [items, setItems] = useState(['우유', '빵']);
  function handleDelete(title: string) {
    setItems(prev => prev.filter(t => t !== title));
  }
  return items.map(t => <TodoItem key={t} title={t} onDelete={handleDelete} />);
}
```

`Pressable`의 `onPress`는 공식 문서에서 "Called after `onPressOut`."로 설명됩니다 (*Pressable*). 손가락을 뗀 뒤 불린다는 뜻입니다.

TypeScript에서는 `onDelete: (title: string) => void`처럼 **"문자열 하나를 받고 아무것도 돌려주지 않는 함수"** 라고 props의 모양을 적어 둡니다. 이렇게 하면 자식이 `onDelete(42)`처럼 잘못 부를 때 편집기가 알려 줍니다 ([[TypeScript Core Syntax and Full-Stack Type Annotations]]).

## 3. 이름이 세 개라서 헷갈린다

| 이름 | 어디에 있나 | 정체 |
|---|---|---|
| `handleDelete` | 부모 | 실제 함수의 이름 |
| `onDelete` | 자식이 받는 props | 부모가 넘긴 **같은 함수**를 자식 쪽에서 부르는 이름 |
| `onPress` (웹은 `onClick`) | `Pressable`(웹은 `<button>`)의 props | "눌렸을 때 이 함수를 불러 달라"고 맡기는 자리 |

1절의 `greet`과 `sayHi`처럼, `onDelete`와 `handleDelete`는 **함수 하나에 붙은 두 개의 이름**입니다.

이름 짓는 관례 (react.dev, *Responding to Events*):
- 자식이 받는 props: "By convention, event handler props should start with `on`, followed by a capital letter."
- 부모의 함수: 예제들은 `handle` + 사건 이름(`handleClick`, `handlePlayClick`)을 씁니다.
- props 이름은 **무엇이 눌렸는지**보다 **앱에서 무슨 일인지**로 짓기를 권합니다: "Naming props after app-specific interactions like `onPlayMovie` gives you the flexibility to change how they're used later."

---

## 4. 자식이 부모에게 값을 올려 보내기

2.1절의 `onDelete(title)`처럼, 자식은 함수를 **부르면서 인수로 값을 건넬** 수 있습니다. 그래서 흐름이 두 방향입니다.

```
부모 ──(props: 데이터와 함수)──▶ 자식        "아래로": 값을 보여 줘
부모 ◀──(함수 호출: 인수로 값)── 자식        "위로": 이런 일이 있었어
```

입력 칸이 대표적인 예입니다. React Native의 `TextInput`: "`onChangeText`: Callback that is called when the text input's text changes. Changed text is passed as a single string argument to the callback handler." (*TextInput*) 자식(`TextInput`)이 바뀐 글자를 인수로 넣어 부모의 함수를 불러 줍니다.

```tsx
// 실행하지 않음
function SearchBox({ onSearch }: { onSearch: (text: string) => void }) {
  return <TextInput placeholder="검색" onChangeText={onSearch} />;   // 괄호 없음: 함수를 그대로 맡김
}

function Screen() {
  const [query, setQuery] = useState('');
  return <SearchBox onSearch={setQuery} />;   // setQuery도 "문자열 하나를 받는 함수"라서 그대로 넘길 수 있음
}
```

### 왜 함수를 부모에 둘까: state 끌어올리기

state를 바꾸는 함수(`setItems`)는 state를 가진 컴포넌트 안에서만 만들어집니다. 그래서 **state가 있는 곳에 함수를 두고, 함수를 아래로 넘깁니다.** react.dev는 이것을 *lifting state up*이라고 부릅니다: "remove state from both of them, move it to their closest common parent, and then pass it down to them via props." 그리고 마지막 단계가 바로 이 레슨의 내용입니다: "passing down the event handler to the child allowed the child to change the parent's state." (*Sharing State Between Components*)

## 5. 가장 흔한 실수: 괄호

```tsx
<Pressable onPress={handleClear}>             // ✅ 함수를 넘김 (인수가 필요 없을 때)
<Pressable onPress={() => onDelete(title)}>   // ✅ "나중에 이렇게 불러 줘"라는 새 함수를 넘김
<Pressable onPress={onDelete(title)}>         // ❌ 렌더하는 순간 지금 불러 버림
```

### 직접 해 보기 (웹 React에서 실행함)

```jsx
function WrongItem({ onDelete }) {
  return <button onClick={onDelete('지금 바로!')}>잘못된 버튼</button>;
}
// <WrongItem onDelete={(v) => console.log(`[렌더 중에 호출됨] ${v}`)} /> 를 렌더만 함 (클릭 안 함)
```

```
[렌더 중에 호출됨] 지금 바로!
```

클릭하지 않았는데 불렸습니다. react.dev: "the `()` at the end of `handleClick()` fires the function *immediately* during rendering, without any clicks. This is because JavaScript inside the JSX `{` and `}` executes right away." 화살표 함수로 감싸면 "this creates a function to be called later." (*Responding to Events*)

부모 함수가 `setItems`처럼 state를 바꾸는 함수라면 더 나쁩니다. 렌더 중에 state가 바뀌고 → 다시 렌더하고 → 또 불리는 일이 되풀이될 수 있습니다 (판단: 위 설명과 [[렌더링 첫걸음 04 - 렌더와 커밋|레슨 04]]의 "state를 바꾸면 다시 렌더"에서).

> [!tip] 한눈에 구별하기
> `{ }` 안에 `이름(…)`이 **바로** 보이면 "지금 부르기", `() =>`로 감싸져 있거나 이름만 있으면 "나중에 부르기"입니다.

## 6. 정리

| 낱말 | 뜻 |
|---|---|
| 함수는 값 | 변수에 담고, props로 넘기고, 나중에 부를 수 있음 |
| `fn` vs `fn()` | 함수 자체(리모컨) vs 지금 호출한 결과(누르기) |
| 이벤트 핸들러 props | 부모가 자식에게 "이 일이 생기면 불러 줘"라고 넘기는 함수. 이름은 `on`으로 시작 |
| `handleXxx` | 부모가 정의한 실제 함수의 관례적 이름 |
| 값 올려 보내기 | 자식이 `onXxx(값)`처럼 인수를 넣어 부름 |
| state 끌어올리기 | state를 공통 부모에 두고, 값과 바꾸는 함수를 아래로 넘김 |

## 7. 자주 하는 실수

| 실수 | 결과 | 바로잡기 |
|---|---|---|
| `onPress={onDelete(title)}` | 렌더할 때 바로 불림 (5절, 실행 결과) | `onPress={() => onDelete(title)}` |
| 자식이 받은 `onDelete`를 어디에서도 부르지 않음 (`onPress`에 연결하지 않음) | 버튼을 눌러도 아무 일도 없음 | 자식 안에서 `onDelete(…)`를 **누가, 언제** 부르는지 확인 (8절 Q4) |
| 부모의 state를 자식이 직접 바꾸려 함 (`props.items.push(…)`) | props는 읽기 전용이라 화면이 안 바뀌거나 꼬임 ([[렌더링 첫걸음 03 - React 첫 만남\|레슨 03]] 4절) | 부모의 바꾸는 함수를 넘겨받아 부름 |
| 인수가 필요한 함수를 그냥 넘김: `onPress={onDelete}` | `onDelete`가 `title` 대신 이벤트 객체를 받음. `onPress`의 타입은 `({nativeEvent: PressEvent}) => void` (*Pressable*) | `() => onDelete(title)`로 원하는 값을 직접 넣음 |
| `useCallback`에 의존성을 빠뜨림 | 오래된 state를 기억해 삭제한 항목이 되살아남 (9.2절, 실행 결과) | 의존성을 채우거나 `setItems(prev => …)` 사용 |

## 8. 확인 퀴즈

**Q1.** 다음 중 버튼을 **눌렀을 때만** `save('메모')`가 실행되는 것은?
① `onPress={save('메모')}` ② `onPress={() => save('메모')}` ③ `onPress={save}`

> [!question]- 정답 보기
> ②입니다. ①은 렌더할 때 바로 실행됩니다. ③은 눌렀을 때 실행되지만 `'메모'`가 아니라 `onPress`가 넘기는 이벤트 객체(`{nativeEvent: …}`)를 받습니다.

**Q2.** 아래에서 `onSelect`와 `handleSelect`는 같은 함수인가요?
```tsx
function Parent() {
  function handleSelect(id: number) { /* … */ }
  return <Child onSelect={handleSelect} />;
}
function Child({ onSelect }: { onSelect: (id: number) => void }) { /* … */ }
```

> [!question]- 정답 보기
> 네, 같은 함수입니다. 부모 쪽 이름이 `handleSelect`, 자식이 받은 props 이름이 `onSelect`입니다.

**Q3.** 자식이 `onDelete('우유')`를 부르면 화면은 어떤 순서로 바뀌나요?

> [!question]- 정답 보기
> 부모의 `handleDelete('우유')` 실행 → `setItems`로 state 변경 → 부모 다시 렌더 → 자식들이 새 props로 다시 렌더 → 화면에 반영 (2.1절 실행 결과, [[렌더링 첫걸음 04 - 렌더와 커밋|레슨 04]]).

**Q4.** 남이 짠 코드에서 `onRefresh`라는 props가 무슨 일을 하는지 알고 싶습니다. 어디를 보면 될까요?

> [!question]- 정답 보기
> 두 곳입니다. ① 자식 안에서 `onRefresh(…)`를 **부르는 곳**: 언제, 어떤 값으로 부르는지. ② 부모에서 `onRefresh={…}`에 **넣은 함수**: 실제로 무슨 일을 하는지. 보통 ②가 `handleRefresh`이고, 그 본문에서 state를 바꿉니다.

**Q5.** `TextInput`에 `onChangeText={setQuery}`처럼 괄호 없이 `setQuery`를 넘겨도 되는 이유는?

> [!question]- 정답 보기
> `onChangeText`는 바뀐 글자를 **문자열 하나**로 넣어 부르고, `setQuery`도 값 하나를 받는 함수이기 때문입니다. 받는 모양이 맞으면 감쌀 필요가 없습니다.

## 9. 더 깊이 (심화)

### 9.1 렌더할 때마다 새 함수가 생긴다

부모 컴포넌트 함수 안의 `function handleDelete…`나 `() => …`는 **부모가 렌더될 때마다 새로 만들어집니다**. react.dev 예제의 주석도 같은 말을 합니다: "Every time the theme changes, this will be a different function..." (*useCallback*)

보통은 문제가 되지 않습니다. 다만 자식을 [`memo`](https://react.dev/reference/react/memo)로 감싸 "props가 같으면 다시 렌더하지 않기"를 해 두었다면, 함수가 매번 새것이므로 props가 달라졌다고 판단됩니다. `memo`는 props를 하나씩 `Object.is`로 비교합니다 (*memo*).

직접 해 보기 (웹 React에서 실행함, `Row`는 `memo`로 감쌈):

```
--- memo 자식, 그냥 함수
[Parent 렌더] n=0
  [Row 렌더] 매번 새 함수
 (부모의 +1 클릭)
[Parent 렌더] n=1
  [Row 렌더] 매번 새 함수        ← props의 함수가 새것이라 다시 렌더
--- memo 자식, useCallback
[Parent 렌더] n=0
  [Row 렌더] useCallback
 (부모의 +1 클릭)
[Parent 렌더] n=1               ← 같은 함수라서 Row는 건너뜀
```

`useCallback`은 "caches a function between re-renders until its dependencies change." (*useCallback*) 그러나 성능을 위한 도구일 뿐입니다: "**You should only rely on `useCallback` as a performance optimization.** If your code doesn't work without it, find the underlying problem and fix it first." 또 React Compiler를 쓰면 "automatically memoizes values and functions, reducing the need for manual `useCallback` calls." (*useCallback*) 처음에는 `useCallback` 없이 쓰고, 측정해서 느릴 때 더합니다.

### 9.2 오래된 값을 기억하는 함수

함수는 **만들어진 렌더의 값**을 기억합니다 ([[JS 첫걸음 10 - 스코프와 클로저|JS 첫걸음 10]]의 클로저, [[렌더링 첫걸음 03 - React 첫 만남|레슨 03]]의 스냅샷). `useCallback`의 의존성 배열에서 `items`를 빠뜨리면, 함수는 **첫 렌더의 `items`** 를 계속 씁니다.

```jsx
const stale = useCallback((t) => setItems(items.filter(x => x !== t)), []);       // items를 빠뜨림
const safe  = useCallback((t) => setItems(prev => prev.filter(x => x !== t)), []); // 이전 값을 함수로 받음
```

처음 값 `['우유', '빵', '달걀']`에서 "우유", 그다음 "빵"을 지운 결과 (웹 React에서 실행함):

```
--- stale: 첫 삭제 후 [빵,달걀] → 두 번째 삭제 후 [우유,달걀]
--- safe:  첫 삭제 후 [빵,달걀] → 두 번째 삭제 후 [달걀]
```

`stale`은 두 번째 삭제 때 첫 렌더의 목록(우유 포함)에서 빵만 빼서, **지웠던 우유가 되살아났습니다**. `setItems(prev => …)`처럼 이전 값을 함수로 받으면 언제 불려도 최신 값에서 계산합니다 ([[렌더링 첫걸음 03 - React 첫 만남|레슨 03]] 6.2절과 같은 원리).
