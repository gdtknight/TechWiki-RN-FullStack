# JS 첫걸음 10 - 스코프와 클로저

> **이전**: [[JS 첫걸음 09 - 객체|09 객체]] · **다음**: [[JS 첫걸음 11 - 비동기 기초|11 비동기 기초]] · **목록**: [[JS 첫걸음 00 - 로드맵|로드맵]]

## 이 레슨에서 배우는 것

1. **스코프**: 변수가 "보이는" 범위
2. 전역 변수, 지역 변수, 블록 스코프
3. 안에서는 밖이 보이고, 밖에서는 안이 안 보이는 규칙 (**스코프 체인**)
4. 같은 이름의 변수가 안팎에 있을 때
5. **클로저**: 함수가 태어난 곳의 변수를 기억하는 것
6. 클로저를 쓰는 곳과 조심할 점

> 이 레슨은 시리즈에서 가장 어려운 편입니다. 한 번에 다 이해하지 못해도 괜찮습니다. 예제를 콘솔에서 직접 실행해 보면서 천천히 읽으세요.

## 1. 스코프란?

### 비유로 이해하기: 우리 집과 우리 동네

- **동네 놀이터**(전역)는 동네 사람 **누구나** 쓸 수 있습니다.
- **우리 집 거실**(함수 안)은 **우리 가족만** 씁니다. 옆집 사람은 우리 집 거실에 뭐가 있는지 모릅니다.
- **내 방 서랍**(블록 안)은 **나만** 엽니다.
- 그런데 우리 가족은 집 밖으로 나가 **동네 놀이터도 쓸 수 있습니다**. 안에서는 바깥이 보이는 것이죠.

**스코프**(scope)는 변수가 **보이는 범위**, 즉 그 변수를 쓸 수 있는 영역입니다. 입문서: "Scope defines where you can access a certain variable." (p.155) MDN: "If a variable or expression is not in the current scope, it will not be available for use."

[[JS 첫걸음 02 - 변수|레슨 02]]의 5절에서 "블록 스코프"를 잠깐 봤고, [[JS 첫걸음 06 - 반복문|레슨 06]]에서 `for (let i …)`의 `i`가 반복문 밖에서 안 보이는 것도 봤습니다. 이번 레슨에서 한꺼번에 정리합니다.

## 2. 세 가지 범위

### 2.1 전역 변수: 어디서나 보임

함수나 블록 **밖**, 가장 바깥에서 만든 변수는 **어디서나** 쓸 수 있습니다. 이것을 **전역 변수**(global variable)라고 합니다 (입문서 p.159).

```js
const school = "햇살초등학교";

function introduce() {
  console.log(`우리 학교는 ${school}`);   // 함수 안에서도 보임
}

introduce();          // 우리 학교는 햇살초등학교
console.log(school);  // 햇살초등학교
```

### 2.2 지역 변수: 함수 안에서만 보임

**함수 안**에서 만든 변수는 그 함수 안에서만 보입니다. 이것을 **지역 변수**(local variable)라고 합니다 (입문서 p.155–156).

```js
function makeSnack() {
  const snack = "떡볶이";
  console.log(`간식: ${snack}`);
}

makeSnack();          // 간식: 떡볶이
console.log(snack);   // ❌ ReferenceError: snack is not defined
```

**매개변수**도 지역 변수입니다 (입문서 p.155: "The function parameters ... are also local variables").

```js
function greet(petName) {
  console.log(petName);
}

greet("초코");          // 초코
console.log(petName);   // ❌ ReferenceError: petName is not defined
```

함수 안의 값을 밖에서 쓰고 싶다면, [[JS 첫걸음 07 - 함수|레슨 07]]의 **`return`으로 값을 돌려받습니다**. 입문서도 이렇게 설명합니다 (p.156): "if you need their values outside a function, you can return the values."

### 2.3 블록 스코프: `{ }` 안에서만 보임

`let`과 `const`는 함수뿐 아니라 **`if`, `for` 같은 모든 `{ }`** 안에서만 보입니다 (입문서 p.157: "let is actually not function-scoped but block-scoped"). MDN *Scope*: "identifiers declared with certain syntaxes, including `let`, `const`, `class`, ... can belong to an additional scope." (블록 스코프)

```js
if (true) {
  const secret = "비밀";
  var leak = "새어 나감";
}

console.log(leak);     // 새어 나감   ← var는 블록을 무시
console.log(secret);   // ❌ ReferenceError: secret is not defined
```

레슨 02에서 `var`를 쓰지 않기로 한 이유가 바로 이것입니다. `var`는 `if`나 `for`의 울타리를 무시하고 새어 나갑니다 (입문서 p.157).

| 선언 | 함수 `{ }` | `if`, `for` 등의 `{ }` |
|---|---|---|
| `let`, `const` | 안에서만 보임 | **안에서만 보임** |
| `var` | 안에서만 보임 | 밖에서도 보임 (새어 나감) |

## 3. 안에서는 밖이 보이고, 밖에서는 안이 안 보인다

### 3.1 스코프 체인

함수 안에 함수가 있으면, 범위도 **양파 껍질처럼 겹겹이** 쌓입니다.

```js
const a = "전역 a";

function outer() {
  const b = "outer의 b";

  function inner() {
    const c = "inner의 c";
    console.log(a, "/", b, "/", c);   // 셋 다 보임
  }

  inner();
  console.log(typeof c);   // undefined  ← 바깥에서 안쪽 c는 안 보임
}

outer();
```

결과:

```
전역 a / outer의 b / inner의 c
undefined
```

`inner` 안에서 변수를 찾을 때, 엔진은 이렇게 찾습니다.

1. 먼저 **자기 안**(`inner`)에서 찾습니다 → `c` 발견
2. 없으면 **한 겹 바깥**(`outer`)에서 찾습니다 → `b` 발견
3. 그래도 없으면 **가장 바깥**(전역)에서 찾습니다 → `a` 발견
4. 끝까지 없으면 `ReferenceError`

이렇게 안에서 밖으로 이어진 찾기 경로를 **스코프 체인**(scope chain)이라고 합니다. [[2015-인사이드 자바스크립트]]는 이 경로를 알아야 "현재 사용되는 변수가 어디에서 선언된 변수인지 정확히 알 수 있다"고 설명합니다 (PDF p.148).

MDN *Scope*: "child scopes have access to parent scopes, but not vice versa." 입문서의 중첩 함수 예도 같은 규칙을 보여 줍니다 (p.165–166): 안쪽 함수는 바깥 변수에 접근할 수 있지만, 그 반대는 안 됩니다.

### 3.2 어디서 **불렀는지**가 아니라 어디서 **만들었는지**

함수가 어떤 바깥 변수를 볼 수 있는지는 **코드에서 함수를 쓴(만든) 위치**로 정해집니다. MDN: "lexical scoping uses the location where a variable is declared within the source code to determine where that variable is available." 이것을 **렉시컬 스코프**(lexical scope)라고 합니다. "렉시컬"은 "코드에 적힌 대로"라는 뜻으로 이해하면 됩니다 (판단).

## 4. 안팎에 같은 이름이 있으면?

안쪽에서 같은 이름으로 변수를 만들면, 안쪽에서는 **안쪽 변수가 우선**입니다. 바깥 변수는 그대로입니다 (입문서 p.160).

```js
const color = "빨강";

function paint() {
  const color = "파랑";      // 바깥 color와 다른, 새 변수
  console.log("안:", color);
}

paint();                     // 안: 파랑
console.log("밖:", color);   // 밖: 빨강
```

스코프 체인에서 **가까운 것부터** 찾기 때문입니다 (3.1절). 입문서는 이렇게 이름이 겹치면 헷갈리니 **피하는 것이 좋다**고 합니다 (p.160: "It is usually better to avoid this.").

## 5. 조심: 선언 없이 대입하면 전역이 된다

`let`이나 `const` 없이 변수에 값을 넣으면 어떻게 될까요? (입문서 p.161)

```js
function confuse() {
  oops = "전역이 되어 버림";   // let/const를 빠뜨림
}

confuse();
console.log(oops);   // 전역이 되어 버림  ← 함수 밖에서 보임!
```

함수 안에서 만들었는데 **전역 변수가 되어 버렸습니다.** 입문서는 이것을 "terrible practice(아주 나쁜 습관)"라고 강하게 경고합니다 (p.161).

다행히 **엄격 모드**(strict mode)에서는 이렇게 쓰면 에러가 납니다. MDN: "Strict mode makes it impossible to accidentally create global variables." 파일 맨 위에 `"use strict";`를 쓰면 됩니다.

```js
"use strict";
function confuse() {
  oops = "전역이 되어 버림";
}
confuse();   // ❌ ReferenceError: oops is not defined
```

레슨 12에서 배울 **모듈**은 처음부터 엄격 모드입니다. MDN: "The entire contents of JavaScript modules are automatically in strict mode". 그래도 가장 좋은 방법은 **항상 `let`이나 `const`를 붙이는 것**입니다.

## 6. 클로저

### 6.1 이상한 일

[[2015-인사이드 자바스크립트]] 예제 5-7을 `let`/`const`로 바꿔서 봅니다 (PDF p.156–157).

```js
function outerFunc() {
  const x = 10;
  const innerFunc = function () {
    console.log(x);
  };
  return innerFunc;   // 함수를 돌려줌 (레슨 07: 함수도 값)
}

const inner = outerFunc();   // outerFunc는 여기서 실행을 마침
inner();                     // 10
```

이상하지 않나요? `x`는 `outerFunc`의 **지역 변수**입니다. `outerFunc`는 이미 실행을 끝냈는데, `inner()`를 부르면 여전히 `x`의 값 `10`이 나옵니다.

### 6.2 클로저란?

`innerFunc`는 **자기가 만들어진 곳(`outerFunc` 안)의 변수를 기억**하고 있습니다. 이렇게 함수가 태어난 곳의 변수를 기억하는 것을 **클로저**(closure)라고 합니다.

- MDN: "A closure is the combination of a function bundled together (enclosed) with references to its surrounding state (the lexical environment). In other words, a closure gives a function access to its outer scope."
- [[2015-인사이드 자바스크립트]]는 쉽게 풀어 이렇게 정의합니다 (PDF p.158): "이미 생명 주기가 끝난 외부 함수의 변수를 참조하는 함수를 클로저라고 한다."

### 비유로 이해하기: 소풍 가방

엄마가 아이에게 도시락을 싸서 가방에 넣어 줍니다. 아이는 집을 떠나 소풍을 가도 **가방 속 도시락을 꺼내 먹을 수 있습니다.** 집(바깥 함수)은 멀리 있지만 가방(클로저)이 집에서 챙긴 것을 들고 다니는 것입니다 (판단). [[JavaScript Core Syntax and Modern ES6+ Fundamentals]] 1.5절의 표도 클로저를 "배낭을 멘 함수"로 비유합니다.

### 6.3 예: 카운터

클로저를 가장 잘 보여 주는 예입니다.

```js
function makeCounter() {
  let count = 0;          // 바깥 함수의 지역 변수
  return function () {
    count++;              // 기억해 둔 count를 바꿈
    return count;
  };
}

const counter = makeCounter();
console.log(counter());   // 1
console.log(counter());   // 2
console.log(counter());   // 3
```

`counter`는 부를 때마다 숫자가 하나씩 올라갑니다. `count`가 사라지지 않고 **계속 기억되기** 때문입니다.

`makeCounter()`를 **다시 부르면 새 가방**이 만들어집니다.

```js
const counter2 = makeCounter();
console.log(counter2());   // 1  ← 새 count, 0부터
console.log(counter());    // 4  ← 원래 counter는 자기 count를 계속 기억
```

그리고 바깥에서는 `count`를 **직접 볼 수도, 바꿀 수도 없습니다.**

```js
console.log(typeof count);   // undefined
```

## 7. 클로저는 어디에 쓰나요?

### 7.1 값을 숨겨서 지키기

6.3절의 `count`처럼, 클로저 안의 변수는 **정해진 함수를 통해서만** 바꿀 수 있습니다. 실수로 엉뚱한 곳에서 값을 바꾸는 일을 막을 수 있습니다. MDN은 이것을 "emulate private methods using closures"라고 설명하고, [[2015-인사이드 자바스크립트]]는 "함수의 캡슐화"라고 부릅니다 (PDF p.164–166).

```js
function createPiggyBank() {
  let money = 0;                         // 바깥에서 직접 못 만지는 돈
  return {
    deposit(amount) { money += amount; },
    getMoney() { return money; },
  };
}

const myBank = createPiggyBank();
myBank.deposit(1000);
myBank.deposit(500);
console.log(myBank.getMoney());   // 1500
console.log(myBank.money);        // undefined  ← 직접은 못 꺼냄
```

[[JS 첫걸음 09 - 객체|레슨 09]]의 메서드와 클로저를 함께 쓴 모양입니다.

### 7.2 함수를 찍어 내는 함수

설정값을 기억하는 함수를 여러 개 만들 수 있습니다. MDN의 `makeAdder` 예: "defined a function `makeAdder(x)`, that takes a single argument `x`, and returns a new function."

```js
function makeAdder(x) {
  return function (y) {
    return x + y;
  };
}

const add5 = makeAdder(5);    // x = 5를 기억
const add10 = makeAdder(10);  // x = 10을 기억

console.log(add5(2));    // 7
console.log(add10(2));   // 12
```

### 7.3 사실 이미 써 봤어요

[[JS 첫걸음 07 - 함수|레슨 07]]의 콜백, [[JS 첫걸음 08 - 배열|레슨 08]]의 `filter(s => s >= limit)`처럼, 콜백 안에서 바깥 변수를 쓸 때마다 클로저가 동작하고 있었습니다. MDN: "In JavaScript, closures are created every time a function is created, at function creation time."

> [!note] React와의 연결
> React의 화면 함수 안에서 만든 이벤트 처리 함수도 클로저입니다. 그래서 "예전 값을 기억하고 있는" 버그(Stale Closure)가 생기기도 합니다. 시리즈를 마친 뒤 [[JavaScript Execution Context, Closures, and Prototype]]에서 볼 수 있습니다.

## 8. 클로저를 쓸 때 조심할 점

### 8.1 기억한 값은 계속 바뀔 수 있다

클로저가 기억하는 것은 **그때의 값을 찍은 사진**이 아니라 **변수 자체**입니다. 그래서 부를 때마다 값이 바뀔 수 있습니다 ([[2015-인사이드 자바스크립트]] 예제 5-14, PDF p.167–168).

```js
function outerFunc(argNum) {
  let num = argNum;
  return function (x) {
    num += x;
    console.log("num: " + num);
  };
}

const exam = outerFunc(40);
exam(5);     // num: 45
exam(-10);   // num: 35  ← 40이 아니라 45에서 시작
```

### 8.2 반복문 + `var` + 나중에 실행되는 함수

클로저 설명에 "단골손님처럼 등장하는" 함정입니다 ([[2015-인사이드 자바스크립트]] PDF p.168).

```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 10);
}
```

1, 2, 3을 기대했지만 결과는:

```
4
4
4
```

`var`로 만든 `i`는 **반복 전체가 하나를 함께 씁니다.** `setTimeout`의 함수가 실행될 때는 반복이 이미 끝나 `i`가 4가 되어 있습니다 ([[2015-인사이드 자바스크립트]] PDF p.169).

**`let`으로 바꾸면 해결됩니다.** `let`은 반복할 때마다 **새 `i`** 를 만들어서 각 함수가 자기 `i`를 기억합니다. MDN: "If you don't want to use more closures, you can use the `let` or `const` keyword."

```js
for (let i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 10);
}
// 1
// 2
// 3
```

`var`를 쓰지 않는 또 하나의 이유입니다.

## 9. 맛보기: 즉시 실행 함수 (IIFE)

함수를 만들자마자 **바로 실행**하는 모양도 있습니다. **즉시 실행 함수**(IIFE)라고 부릅니다 (입문서 p.161–162).

```js
(function () {
  const msg = "IIFE!";
  console.log(msg);
})();
// IIFE!

console.log(typeof msg);   // undefined  ← 밖에서는 안 보임
```

함수를 괄호로 감싸고 끝에 `()`를 붙입니다. 안에서 만든 변수가 밖으로 새지 않게 하는 용도로 예전 코드에서 많이 썼습니다. 지금은 블록 `{ }`과 `let`/`const`, 그리고 레슨 12의 모듈로 대부분 대신합니다 (판단). 다른 사람의 코드에서 보면 알아볼 수 있으면 충분합니다.

## 10. 정리

| 낱말 | 뜻 |
|---|---|
| 스코프 | 변수가 보이는(쓸 수 있는) 범위 |
| 전역 변수 | 가장 바깥에서 만든 변수. 어디서나 보임 |
| 지역 변수 | 함수 안에서 만든 변수와 매개변수. 그 함수 안에서만 보임 |
| 블록 스코프 | `let`·`const`는 `{ }` 안에서만 보임. `var`는 블록을 무시 |
| 스코프 체인 | 변수를 안에서 밖으로 차례로 찾는 경로 |
| 렉시컬 스코프 | 함수가 볼 수 있는 범위는 **만든 위치**로 정해짐 |
| 엄격 모드 | `"use strict";`. 선언 없는 대입을 에러로 막음. 모듈은 자동 적용 |
| 클로저 | 함수 + 그 함수가 태어난 곳의 변수들. 바깥 함수가 끝나도 기억함 |
| IIFE | 만들자마자 실행하는 함수. `(function () { ... })();` |

## 11. 자주 하는 실수

| 잘못 쓴 코드 | 결과 | 무엇이 문제인가 |
|---|---|---|
| 함수 안에서 만든 변수를 밖에서 씀 | `ReferenceError: … is not defined` | 지역 변수입니다. 값이 필요하면 `return`으로 돌려받습니다. |
| `if` 안에서 `const`로 만든 변수를 `if` 밖에서 씀 | `ReferenceError` | 블록 스코프입니다. 밖에서 쓸 변수는 블록 **밖에서** 먼저 만듭니다. |
| `let`/`const` 없이 `oops = 1;` | 전역 변수가 생김 (엄격 모드에서는 `ReferenceError`) | 항상 `let`이나 `const`를 붙입니다. |
| 안쪽에서 바깥과 같은 이름으로 변수를 만들고, 바깥 값이 바뀌길 기대 | 바깥 값은 그대로 | 안쪽에 새 변수가 생긴 것입니다 (4절). 바깥 변수를 바꾸려면 `const`/`let` 없이 대입합니다. |
| `for (var i …)` 안에서 `setTimeout` | 모두 마지막 값 | `let`으로 바꿉니다 (8.2절). |

## 12. 확인 퀴즈

**Q1.** 아래 코드의 출력은?
```js
let x = 1;
function f() {
  let x = 2;
  return x;
}
console.log(f(), x);
```

> [!question]- 정답 보기
> `2 1`입니다. 함수 안의 `x`는 바깥 `x`와 다른 새 변수입니다. 바깥 `x`는 그대로 1입니다.

**Q2.** 아래 코드의 마지막 줄은 무엇을 출력할까요? 에러가 난다면 이유는?
```js
function setUp() {
  const level = 3;
}
setUp();
console.log(level);
```

> [!question]- 정답 보기
> `ReferenceError: level is not defined`가 납니다. `level`은 `setUp`의 지역 변수라서 함수 밖에서는 보이지 않습니다.

**Q3.** 아래 코드의 출력은?
```js
let total = 0;
function addToTotal(n) {
  total += n;
}
addToTotal(5);
addToTotal(3);
console.log(total);
```

> [!question]- 정답 보기
> `8`입니다. `total`은 전역 변수이고, 함수 안에서 `let`/`const` 없이 `total += n`으로 바꿨으므로 바깥 `total`이 바뀝니다 (안쪽에서 바깥이 보이는 규칙).

**Q4.** 아래 코드의 마지막 줄은 무엇을 출력할까요?
```js
function makeStep() {
  let n = 0;
  return () => {
    n += 10;
    return n;
  };
}
const s1 = makeStep();
const s2 = makeStep();
s1();
s1();
console.log(s1(), s2());
```

> [!question]- 정답 보기
> `30 10`입니다. `s1`과 `s2`는 각자 자기 `n`을 기억합니다. `s1`은 세 번 불려 30, `s2`는 처음 불려 10입니다.

**Q5.** 인사말을 기억하는 함수를 만드는 `makeGreeter(greeting)`을 완성하세요. `makeGreeter("안녕")("민수")`가 `"안녕, 민수!"`가 되어야 합니다.

> [!question]- 정답 보기
> ```js
> function makeGreeter(greeting) {
>   return (name) => `${greeting}, ${name}!`;
> }
> const hello = makeGreeter("안녕");
> console.log(hello("민수"));   // 안녕, 민수!
> ```

**Q6.** 아래 코드는 왜 `4 4 4`를 출력하고, 어떻게 고치면 `1 2 3`이 될까요?
```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 10);
}
```

> [!question]- 정답 보기
> `var`로 만든 `i`는 반복 전체가 하나를 함께 쓰는데, `setTimeout`의 함수는 반복이 끝난 뒤(`i`가 4일 때) 실행되기 때문입니다. `var`를 `let`으로 바꾸면 반복마다 새 `i`가 생겨 1, 2, 3이 출력됩니다.

**Q7. (직접 해 보기)** 6.3절의 `makeCounter`를 고쳐서, 부를 때마다 1이 아니라 **2씩** 올라가는 카운터를 만들어 보세요.

> [!question]- 예시 답안
> ```js
> function makeCounter() {
>   let count = 0;
>   return function () {
>     count += 2;
>     return count;
>   };
> }
> const counter = makeCounter();
> console.log(counter(), counter(), counter());   // 2 4 6
> ```
