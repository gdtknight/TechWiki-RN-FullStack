# 렌더링 첫걸음 08 - 앱과 화면의 생명 주기

> **이전**: [[렌더링 첫걸음 07 - React Native는 화면을 어떻게 그릴까|07 React Native는 화면을 어떻게 그릴까]] · **다음**: [[렌더링 첫걸음 09 - 버튼 하나를 누르면|09 버튼 하나를 누르면]] · **목록**: [[렌더링 첫걸음 00 - 로드맵|로드맵]]

## 이 레슨에서 배우는 것

1. 생명 주기가 **세 겹**이라는 것: 컴포넌트, 화면, 앱
2. **앱 생명 주기**: `AppState`의 `active` / `background` / `inactive`
3. **화면은 떠나도 언마운트되지 않는다** (React Navigation)
4. 화면 **포커스**에 맞춘 Effect: `useFocusEffect`, `useIsFocused`, `focus`·`blur` 이벤트
5. 웹에서는 무엇이 이에 해당하는지

> React Native 예제는 앱 실행 환경이 없어 **실행하지 않았습니다**. React Native, React Navigation(7.x, 현재 기본 문서 버전), Expo 공식 문서를 근거로 씁니다.

## 1. 생명 주기는 세 겹

### 비유로 이해하기: 건물, 방, 가구

| 비유 | 생명 주기 | 언제 바뀌나 | 도구 |
|---|---|---|---|
| 가구 | **컴포넌트** | 마운트 · 업데이트 · 언마운트 | `useEffect` ([[렌더링 첫걸음 05 - 생명 주기와 useEffect\|레슨 05]]) |
| 방 | **화면** | 포커스 · 블러 (보이는 화면이 바뀜) | `useFocusEffect`, `useIsFocused` |
| 건물 | **앱** | 포그라운드 · 백그라운드 | `AppState` |

웹 React 앱에서는 보통 다른 페이지로 가면 이전 페이지 컴포넌트가 사라져서, **"방을 나간다 = 가구를 치운다"** 였습니다. React Native 앱에서는 방을 나가도 가구가 **그대로 남아 있습니다**. 그래서 세 겹을 따로 생각해야 합니다.

## 2. 앱 생명 주기: `AppState`

### 2.1 세 가지 상태

"`AppState` can tell you if the app is in the foreground or background, and notify you when the state changes." (reactnative.dev *AppState*)

| 상태 | 공식 설명 | 예 |
|---|---|---|
| `active` | "The app is running in the foreground" | 사용자가 앱을 보고 있음 |
| `background` | "The app is running in the background." | 다른 앱으로 감, 홈 화면, (Android) 다른 `Activity` |
| `inactive` (iOS만) | "a state that occurs when transitioning between foreground & background, and during periods of inactivity" | 멀티태스킹 화면, 알림 센터, 전화가 옴 |

### 2.2 직접 해 보기: "돌아왔어요" 감지하기

공식 문서의 예제(일부, 실행하지 않음):

```jsx
const appState = useRef(AppState.currentState);

useEffect(() => {
  const subscription = AppState.addEventListener('change', nextAppState => {
    if (
      appState.current?.match(/inactive|background/) &&
      nextAppState === 'active'
    ) {
      console.log('App has come to the foreground!');
    }
    appState.current = nextAppState;
  });

  return () => {
    subscription.remove();
  };
}, []);
```

읽는 법:
- `addEventListener('change', …)`로 상태 변화를 **구독**하고, 정리 함수에서 `subscription.remove()`로 **해지**합니다. [[렌더링 첫걸음 05 - 생명 주기와 useEffect|레슨 05]] 5.2절의 "구독했으면 해지"와 같은 모양입니다.
- 이전 상태를 `useRef`에 기억해 두고, `inactive` 또는 `background` → `active`로 바뀌는 순간을 "포그라운드로 돌아옴"으로 판단합니다.

이렇게 감지해서 **돌아오면 데이터를 새로 고치고**, 백그라운드로 가면 **타이머나 위치 추적을 멈추는** 데 씁니다 (판단).

### 2.3 웹에서는: 탭이 숨겨질 때

웹에는 "앱"은 없지만 **탭** 단위로 비슷한 것이 있습니다. MDN: "When the user minimizes the window, switches to another tab, or the document is entirely obscured by another window, the API sends a `visibilitychange` event" (*Page Visibility API*)

브라우저는 숨은 탭에서 스스로 일을 줄이기도 합니다: "Most browsers stop sending `requestAnimationFrame()` callbacks to background tabs or hidden `<iframe>`s" / "Timers such as `setTimeout()` are throttled in background/inactive tabs" (같은 문서). [[렌더링 첫걸음 02 - 프레임과 이벤트 루프|레슨 02]]에서 배운 rAF가 숨은 탭에서는 불리지 않을 수 있다는 뜻입니다.

| | 웹 | React Native |
|---|---|---|
| 감지 대상 | 문서(탭)가 보이는지 | 앱이 포그라운드인지 |
| 도구 | `document.visibilityState`, `visibilitychange` | `AppState.currentState`, `change` |

## 3. 화면은 떠나도 언마운트되지 않는다

### 3.1 공식 문서의 설명

[[React Navigation]] 문서: "If you're coming from a web background, you might expect that when navigating from route A to route B, A unmounts and remounts when you return. React Navigation works differently" / "Unlike web browsers, React Navigation doesn't unmount screens when navigating away." (*Navigation lifecycle*)

`Home` → `Profile`로 이동하고 돌아올 때:

| 동작 | `Home` | `Profile` |
|---|---|---|
| `Home` → `Profile` | **마운트된 채로 남음** ("`Home` stays mounted") | 마운트 |
| 뒤로 가기 | 다시 마운트되지 않고 기존 화면이 보임 ("existing instance is shown") | **언마운트** |

### 3.2 탭까지 섞으면

공식 문서의 예: 탭 두 개(각각 스택)에서 Home → Details로 가고, 탭을 바꿔 Settings → Profile로 가면 "After this sequence of operations is done, all 4 of the screens are mounted!" Home 탭으로 돌아오면 Details 화면이 그대로 보입니다 (*Navigation lifecycle*).

### 3.3 그래서 `useEffect`의 정리 함수는

```jsx
function HomeScreen() {
  useEffect(() => {
    console.log('HomeScreen mounted');
    return () => console.log('HomeScreen unmounted');
  }, []);
  // ...
}
```

(공식 문서 예제 형태, 실행하지 않음)

Home에서 다른 화면으로 가도 `unmounted`는 찍히지 않습니다. 정리 함수는 **화면이 스택에서 완전히 빠질 때** 실행됩니다 (판단: 위 공식 설명과 react.dev *Synchronizing with Effects*의 정리 함수 설명 "one final time when the component unmounts (gets removed)"에서).

> 웹 습관대로 "화면을 떠나면 `useEffect` 정리 함수가 타이머를 멈춰 주겠지"라고 생각하면, **보이지 않는 화면에서 타이머·폴링이 계속 돕니다** (판단).

## 4. 화면 포커스에 맞추기

### 4.1 `useFocusEffect`: 화면이 보일 때만

```jsx
import { useFocusEffect } from '@react-navigation/native';

function ProfileScreen() {
  useFocusEffect(
    React.useCallback(() => {
      // Do something when the screen is focused
      return () => {
        // Do something when the screen is unfocused
        // Useful for cleanup functions
      };
    }, [])
  );
  return <View />;
}
```

(React Navigation *useFocusEffect* 예제, 실행하지 않음)

"The `useFocusEffect` is analogous to React's `useEffect` hook. The only difference is that it only runs if the screen is currently focused." (*useFocusEffect*)

| | `useEffect` | `useFocusEffect` |
|---|---|---|
| 설정 실행 | 마운트, 의존성 변경 | **포커스**될 때, (포커스 중) 의존성 변경 |
| 정리 실행 | 의존성 변경, 언마운트 | "when dependencies change and a new effect is scheduled and when the screen unmounts or **blurs**" |
| 의존성 | 두 번째 인자 배열 | `React.useCallback`의 의존성 배열 |

### 4.2 `useCallback`으로 꼭 감싸기

"To avoid running the effect too often, it's important to wrap the callback in `useCallback` before passing it to `useFocusEffect`" / "If you don't wrap your effect in `React.useCallback`, the effect will run every render if the screen is focused." (*useFocusEffect*)

[[렌더링 첫걸음 03 - React 첫 만남|레슨 03]]에서 본 것처럼 컴포넌트 함수는 렌더마다 다시 실행되고, 그 안의 함수도 매번 **새로 만들어집니다**. `useFocusEffect`는 콜백이 바뀌면 다시 실행하므로, `useCallback`으로 "의존성이 같으면 같은 함수"를 넘겨야 합니다 (판단: 위 공식 문장에서).

### 4.3 화면에서 데이터 가져오기

[[렌더링 첫걸음 06 - Effect 심화|레슨 06]]의 경쟁 상태 문제가 여기서도 똑같이 생깁니다. 공식 문서의 해결법도 같은 모양입니다:

```jsx
useFocusEffect(
  React.useCallback(() => {
    let isActive = true;

    const fetchUser = async () => {
      try {
        const user = await API.fetch({ userId });
        if (isActive) {
          setUser(user);
        }
      } catch (e) {
        // Handle error
      }
    };

    fetchUser();

    return () => {
      isActive = false;
    };
  }, [userId])
);
```

"If you don't ignore the result, then you might end up with inconsistent data due to race conditions in your API calls." (*useFocusEffect*) 레슨 06의 `ignore`가 여기서는 `isActive`입니다.

### 4.4 `useIsFocused`: 포커스에 따라 다르게 그리기

`useIsFocused`는 "returns a boolean indicating whether the screen is focused" (*Navigation lifecycle*). 화면에 "보는 중"/"안 보는 중"을 다르게 그릴 때 씁니다.

주의: "using this hook triggers a re-render for the component when the screen it's in changes focus. This might cause lags during the animation if your component is heavy." (*useIsFocused*) 무거운 부분은 따로 떼어 `React.memo`로 감싸라고 안내합니다 (같은 문서).

### 4.5 `focus`·`blur` 이벤트

"To detect when a screen gains or loses focus, we can listen to `focus` and `blur` events" (*Navigation lifecycle*)

```jsx
React.useEffect(() => {
  const unsubscribe = navigation.addListener('focus', () => {
    console.log('ProfileScreen focused');
  });
  return unsubscribe;
}, [navigation]);
```

(공식 문서 예제, 실행하지 않음)

### 4.6 Expo Router에서는

[[Expo]] Router도 같은 이름의 훅을 `expo-router`에서 제공합니다: "Hook to run an effect whenever a route is focused." / "The passed callback should be wrapped in React.useCallback to avoid running the effect too often." (docs.expo.dev *Router hooks*)

```jsx
import { useFocusEffect } from 'expo-router';
import { useCallback } from 'react';
```

## 5. 무엇을 언제 쓸까

| 하고 싶은 일 | 도구 |
|---|---|
| 컴포넌트가 처음 생길 때 한 번 준비, 사라질 때 정리 | `useEffect(fn, [])` |
| 화면이 보일 때 시작, 안 보이면 멈춤 (폴링, 카메라, 구독) | `useFocusEffect` |
| 화면에 다시 올 때마다 데이터 새로 고침 | `useFocusEffect` (+ `isActive`) |
| 포커스 여부로 다른 UI 그리기 | `useIsFocused` |
| 화면을 떠날 때 **한 번** 할 일 (정리가 아닌 일) | `blur` 이벤트 (9.1절) |
| 앱이 백그라운드로 가면 멈추고, 돌아오면 재개 | `AppState` |
| 보이기 전에 레이아웃 보정 | `useLayoutEffect` ([[렌더링 첫걸음 07 - React Native는 화면을 어떻게 그릴까\|레슨 07]] 5절) |

(판단: 1–4절의 공식 설명을 표로 묶음)

## 6. 정리

| 낱말 | 뜻 |
|---|---|
| `AppState` | 앱이 포그라운드(`active`)·백그라운드(`background`)·전환 중(`inactive`, iOS)인지 알려 주는 API |
| 포커스 / 블러 | 화면이 사용자에게 보이게 됨 / 보이지 않게 됨 |
| 화면이 마운트된 채 남음 | React Navigation은 다른 화면으로 가도 이전 화면을 언마운트하지 않음 |
| `useFocusEffect` | 포커스될 때 실행, 블러·언마운트·의존성 변경 때 정리하는 Effect |
| `useIsFocused` | 포커스 여부(불리언). 바뀔 때 다시 렌더됨 |
| Page Visibility API | 웹에서 탭이 보이는지 알려 주는 API (`visibilitychange`) |

## 7. 자주 하는 실수

| 실수 | 결과 | 바로잡기 |
|---|---|---|
| 화면을 떠나면 `useEffect` 정리가 실행된다고 가정 | 보이지 않는 화면에서 폴링·타이머가 계속 돔 | `useFocusEffect` (3.3, 4.1절) |
| `useFocusEffect`에 콜백을 그대로 넘김 | 포커스 중 렌더마다 Effect 재실행 | `useCallback`으로 감싸기 (4.2절) |
| `useFocusEffect` 안 데이터 가져오기에 정리 없음 | 경쟁 상태 | `isActive` 플래그 (4.3절) |
| 정리 함수에 "떠날 때 할 일"을 넣음 | 의존성 변경·언마운트 때도 실행됨 | `blur` 이벤트 (9.1절) |
| 무거운 화면 전체에서 `useIsFocused` | 전환 애니메이션 중 버벅임 | 무거운 부분 분리 + `React.memo` (4.4절) |
| `AppState` 구독을 해지하지 않음 | 리스너가 쌓임 | `subscription.remove()` (2.2절) |

## 8. 확인 퀴즈

**Q1.** 스택에서 `Home` → `Detail`로 이동했습니다. `Home`의 `useEffect` 정리 함수는 실행될까요?

> [!question]- 정답 보기
> 실행되지 않습니다. React Navigation은 다른 화면으로 가도 이전 화면을 언마운트하지 않습니다. `Home`이 스택에서 빠질 때 실행됩니다.

**Q2.** 채팅 목록 화면이 5초마다 서버를 확인합니다. 다른 화면에 가 있을 때는 멈추게 하려면?

> [!question]- 정답 보기
> `useFocusEffect` 안에서 `setInterval`을 시작하고, 정리 함수에서 `clearInterval`합니다. 콜백은 `useCallback`으로 감쌉니다.
> ```jsx
> useFocusEffect(
>   React.useCallback(() => {
>     const id = setInterval(checkServer, 5000);
>     return () => clearInterval(id);
>   }, [])
> );
> ```

**Q3.** iPhone에서 알림 센터를 내렸습니다. `AppState`는 어떤 값이 될까요?

> [!question]- 정답 보기
> `inactive`입니다. 공식 문서가 iOS의 `inactive` 예로 "opening the Notification Center"를 듭니다.

**Q4.** 웹에서 사용자가 다른 탭으로 가면 동영상을 멈추고 싶습니다. 무엇을 쓸까요?

> [!question]- 정답 보기
> Page Visibility API의 `visibilitychange` 이벤트와 `document.visibilityState`입니다. MDN이 바로 이 예(탭을 바꾸면 동영상 일시 정지)를 듭니다.

**Q5.** `useFocusEffect`의 콜백을 `useCallback`으로 감싸지 않으면 어떻게 될까요?

> [!question]- 정답 보기
> 화면이 포커스된 동안 렌더될 때마다 Effect가 다시 실행됩니다 ("the effect will run every render if the screen is focused").

## 9. 더 깊이 (심화)

### 9.1 정리 함수는 "떠날 때 할 일"이 아니다

React Navigation 문서는 이렇게 하지 말라고 합니다:

```jsx
// ❌ 공식 문서의 "don't do the following" 예
useFocusEffect(
  React.useCallback(() => {
    return () => {
      // Do something that should run on blur
    };
  }, [])
);
```

"The cleanup function runs whenever the effect needs to cleanup, i.e. on `blur`, unmount, dependency change etc. It's not a good place to update the state or do something that should happen on `blur`. You should use the `blur` event instead" (*useFocusEffect*)

[[렌더링 첫걸음 06 - Effect 심화|레슨 06]] 4.2절의 "사건 때문에 하는 일은 이벤트 처리기에서"와 같은 원칙입니다. 정리 함수는 **설정을 되돌리는 것**, 블러는 **사건**입니다 (판단).

### 9.2 `focus` 이벤트 대신 `useFocusEffect`를 쓰는 이유

"Since it's an event, your listener won't be called if the screen was already focused when you subscribed to the event. This also doesn't provide a way to perform a cleanup function when the screen becomes unfocused." / "It re-runs the effect when dependencies change, so you don't need to worry about stale values in your listener." (*useFocusEffect*)

이벤트는 **구독한 뒤에 일어난 일**만 알려 줍니다. `useFocusEffect`는 "지금 포커스된 상태와 맞추기"라서, 이미 포커스된 상태에서도 실행됩니다. 레슨 05 9.1절의 "Effect는 동기화"라는 관점과 같습니다 (판단).

### 9.3 전환 애니메이션이 끝난 뒤에 무거운 일 하기

"The `useFocusEffect` hook runs the effect as soon as the screen comes into focus. This often means that if there is an animation for the screen change, it might not have finished yet." React Navigation은 애니메이션을 네이티브 스레드에서 실행하므로 대개 문제없지만, 무거운 일이면 애니메이션 성능에 영향을 줄 수 있다고 합니다 (*useFocusEffect*).

이 문서는 해결책으로 `InteractionManager.runAfterInteractions`를 제시합니다. 그런데 React Native 0.86 문서는 `InteractionManager`를 "Deprecated — Avoid long-running work and use `requestIdleCallback` instead."로 표시하고, 현재 문서에서는 페이지가 없습니다 (reactnative.dev/docs/0.86/interactionmanager 확인, 최신 경로는 404). *Performance Overview*도 JS 스레드가 한가할 때까지 미루는 방법으로 `requestIdleCallback`을 듭니다. → 레슨 07 4.2절, [[렌더링 첫걸음 02 - 프레임과 이벤트 루프|레슨 02]]의 작업 나누기

### 9.4 `AppState`의 다른 이벤트

| 이벤트 | 플랫폼 | 공식 설명 |
|---|---|---|
| `memoryWarning` | iOS | "Fires when the app receives a memory warning from the operating system." |
| `focus` | Android | "Received when the app gains focus (the user is interacting with the app)." |
| `blur` | Android | 알림 서랍을 내릴 때 등: "`AppState` won't change but the `blur` event will get fired." |

(*AppState*) 화면 포커스(React Navigation의 `focus`/`blur`)와 이름은 같지만 **앱** 단위 이벤트입니다.
